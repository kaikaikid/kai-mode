# scheduling —— 塔台排班算法（启用道 ＋ 调班）

> 塔台技能 §8 的实现细则。**排班是本轮最后一步**（先 push 关票，再补日表），这条顺序约束住在技能正文；
> 本文件只写「排哪几道、怎么补、补谁、怎么调」。判据变了要同步升技能版本，并在日报写「判据变更后全量重排」。

## 零、启用道（唯一开关）

代号：`0`＝王牌 ace、`1`＝主机长 main、`2`＝副机长 deputy、`3`＝二副 second。
写法：`1+2`（默认）、`all`（＝1+2+3）、`1+2+3`；分隔符只认 `+`（全角数字与 `＋` 自动纠正）。
`all` 不含 `0`；要王牌道就单独写，如 `all+0`。

- **读**：`python scripts/lane_spec.py show --repo <仓根>`。
- **优先级**：本轮显式参数（命令参数，或定时器 prompt 里的 `lanes=`）> 状态文件 > 默认 `1+2`。
- **落盘**：显式参数用 `python scripts/lane_spec.py set <代号> --repo <仓根> --source command|timer`
  写进 `paths.state_dir/tower-lanes.json`——定时器下一轮与门卫读同一份，不会各自为政。
- **塔台只排 1/2/3**：`0` 只进集合，不产生日表（`-ace.md` 由王牌写）。
- **停用道**：不建当日表、不补行；未开工的行按 §四 调班并走，**在跑的行不删**，跑空即止。
- 启用道与项目实例 `paths.lanes` 取交集；实例里没有的道写进代号也会被忽略，日报记一句。

## 一、读表与建池

1. 读**启用道**的当日正常日表；删已关票行，保留在飞票行。停用道若已有当日表，只读不改——
   在跑的行留着，未开工的行按 §四 并走。`-ace.md` **只读不写**（王牌唯一写者）。
2. 后备池 ＝ 开放 ＋ `ready-for-agent` ＋ 挂**开放里程碑**的票；未挂里程碑不进池；**排除带加急队列标签的票**。
   若某张加急票已混进正常日表：删掉这一行并在备注写「转王牌」——塔台只删自己写的表，不碰 `-ace.md`。
3. 排序：里程碑到期日（无到期日最后），同里程碑内按票号升序。

## 二、分配：先钉车道，再亲和，后均衡

用户 2026-10-25 口径：有些任务必须在同一机长下完成才是最佳，不能平均分配。

1. **显式钉车道优先**：票带 `main-queue` / `deputy-queue` / `second-queue` ⇒ 必须排进对应车道，
   亲和与均衡不得改排；若该票已在另一张正常日表里，塔台删行并转入指定车道（只改日表，不关票、不写状态）。
   **钉在停用道上的票不并道**：留在池里，日报点名「票 X 钉在未启用的 <道> 道」，等地勤改标或用户显式授权。
   车道标签正本见地勤技能「车道分流」（四条字符串由地勤建与打，塔台只读不改）。
2. **亲和优先**：满足任一条即归同一车道，不为了填满日表拆开——
   a) A 是 B 的前置/解挡票（B 已在飞或已在表）⇒ A 排到 B 的车道；
   b) 同一交付链 / 同一 ADR、spec、验收上下文 / 同一功能族；
   c) 同一文件域或同一组「允许修改」（同域不能并列在飞，但可同车道排队）。
3. **均衡只在独立项之间做**：互不相关的票优先补**可动作票较少**的启用道；
   比较的是可动作票（可开工/在飞），**不是日表行数**——占行、等回执、hold 行不算可动作。
4. 亲和组不拆；池子填不满就一边留短，日报如实记「库存不足/无独立项」，**不凑数开票**。

## 三、补表与写入

1. 给每条启用道补到**协议正本的行数区间**（#1877 拍板：日表是给机长的**任务菜单**，按区间上限排；
   协议的**在飞名额**约束的是机长**并发领工**，不是表的行数）。不足下限从池里补；
   池子真不够才留空并在日报记「库存不足」，**不凑数开票**。
2. 同一张票不得同时进多张正常日表；同一文件域**不并列在飞**（按票面「允许修改」判断）
   —— 同域票**可以进表排队**，机长领工时保证不同时开两张同域票。
3. 日表固定五列：`| 序 | 票号 | 里程碑 | 一句话 | 塔台备注 |`；**票号必须在第 2 列**（A2 只认这一列，
   写在备注里不算）。**状态不写表**，状态看 Issue 评论。

## 四、调班（票换道）

排班时可以把票从一个机长挪给另一个——停用道并回、均衡、解挡都算调班。
但**按票有没有腿分档**，在飞的一张都不动。

| 档 | 判据（票面现读，不看印象） | 能不能挪 |
|---|---|---|
| 未开工 | 无开工评论、无分支、无 scoped commit | **自由挪**，成本 0 |
| 在跑 | 有开工评论 ＋ 分支 ＋ worker 在跑 | **不挪**；等它落判词 |
| 已停 | 有续跑指针、无 worker（卡点／等回执／停） | 可挪，先过下面四条 |
| 待发货 | 判词 `verdict=pass` | 不挪（发货与车道无关） |

「已停」票挪之前四条全过，缺一条就不挪：

1. **可死性三件齐**：票面有判词、分支 HEAD sha 已记、该票工作树无未提交。
2. **原道释放分支**：原车道树切回 `dev`（或 detach）；不释放，目标道 checkout 同一分支会失败。
3. **目标道有名额**：目标道可动作票数未到 worker 预算。
4. **文件域不撞**：目标道没有同域在飞票。

挡法（不许绕过）：

- **钉车道标签优先**：带车道标签的票不自动改排；停用道上的钉道票不并道，只报告。
- **亲和组整组挪**，不拆。
- **停用道并回**：未开工的票回池，按亲和／均衡并进启用道；在跑的留在原表跑到落判词，塔台不补行。
- **塔台是日表唯一写者**：调班只有塔台写，机长只读。别手改日表——手改会绕过下面的留痕。

**移道留痕（先写票面，再挪表）**：

```text
移道：<旧道>→<新道>；原因：<停用道并回／均衡／解挡>；原树已释放：是/否；移道人：塔台 <时间>
```

两条语义写死：

- **日表行消失＝不归我，不等于票取消**；票状态只看 Issue。
- **互斥看票面不看表**：开工评论先写的人赢；新机长开工前回读票面，看到别人的开工评论就停手问。

## 五、排完要留痕

写当日日报（项目配置 `paths.handoff_dir`）：四件事——**启用道代号**、发了哪几张、退了哪张、卡在哪；
**本轮回填／调整了日表也补一句**（如「排班补 N 张」或「库存不足」；按亲和或调班挪表要写明理由与去向）。
整轮无任何实质变化 → 一行「零动作」退出，不硬找活。
