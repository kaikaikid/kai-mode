# dispatch —— 票外派发策略

> 本文是**票外**（独立任务、机动、直接对话场景）派发的正本。
> 票内（一张 issue 的施工／审查）派工卡与回执形状住同目录 [`loop-protocol.md`](loop-protocol.md) §五，本文不重复、也不适用票内。
> 人格文件已退役：本文只写「派什么、给什么、收回什么」，宿主上怎么起新上下文见 `adapters/`。

## 1. 什么时候不派

满足任一，自己做完，不派：

- 单文件小改动、改一处文案、修一个明确局部问题；
- 只需读少量文件或看一两张图；
- 前后步骤紧密耦合，必须持续共享中间推理；
- 派活要花在解释背景和确认结果上的时间，超过任务本身。

## 2. 什么时候值得派

满足任一，且边界能说清，才派：

- 真并行：两项以上互不依赖的调查可同时做；
- 要新上下文：读大量代码／资料会挤占主上下文；
- 要独立视角：安全／架构／验收审查，避免自证；
- 要不同权限：只读调查 vs 可写实现 vs 不许改实现的审查。
- 安全专项：仅当明确要求安全审计／漏洞排查时，挂 `security-audit` 方法（六阶段、长跑、多单元）。

## 3. 谁能派给谁

| 派活方 | 可派 | 不派 |
|---|---|---|
| 主代理（票外对话） | 任意子代理 | — |
| 机长／副机长 | 票内：施工＋审查；机动：只读调查、计划、裁决 | 不派第二个施工到同一文件域；不派裁决子代理裁红线 |
| 塔台 | 不派 | 只排班与发货，派活归机长 |
| 地勤 | 不派 | 只对话、规划、开票 |
| 任何子代理 | 不派（派生深度固定 1 层，宿主侧不给派生工具） | 路由权只在派活方 |

**安全专项不另立人格**：`security-audit` 由父级驱动六阶段——派活方自己编排侦察、覆盖台账、复核与出报告，
把猎取单元派给只读子代理。只有「权限真的不同」才拆上下文：裁决与审查拆得，安全专项不拆。

## 4. 票外轻卡（5 项，缺一项就是让它自己猜）

```text
目标：一句话，说要解决什么，不写实现方案
范围：允许读／改哪些路径；明确不做什么
权限：只读 / 可写指定路径；禁止的动作
验收：什么证据算完成（命令、读数、文件）
交付：结论 / 计划 / 回执 / 判词 / 裁决（只选一种）
```

票内重卡（票号／AC／机检／增量提交）走 [`loop-protocol.md`](loop-protocol.md) §五。

## 5. 回执四要素（票外）

① 结论先行 ② 证据（路径／符号／命令／链接／测试输出）③ 未确认项（假设与风险）④ 建议下一步（只给一个）。

禁止只回「已完成」「看起来没问题」。**无证据的结论＝未完成。**

## 6. 并发与边界

- **只读可并行**：调查、检索、审查之间可同时跑。
- **写默认串行**：同一工作区同一时刻只一个写者；要并行必须文件域不重叠，按域拆、由派活方合并。
- **一文件域一写手**：两个写入方改同一组文件＝互相覆盖，不允许。
- **隔离按车道**：main／deputy／ace 各用自己的车道工作树；票在树里换分支，不为每张票新建一棵。
- **权限与模型**：只读子代理不给写类工具；模型不写死在框架里，用宿主默认，除非项目实例另有配置。
  宿主上怎么落成原生机制见 `adapters/`，不在派工卡里写宿主字段名。

## 7. 失败处理

| 现象 | 处理 |
|---|---|
| 缺范围 | 派活方补范围后重派，不让子代理自行扩大 |
| 越权写入 | 停该子代理，按只读落法重派 |
| 回执无证据 | 视为未完成，要求重做或换上下文 |
| 连续两次失败 | 交回派活方重新规划，不继续堆子代理 |
| 到点没回音 | 记 `unconfirmed`——既不算完成也不算失败；先探活，再决定续派或关闭 |
| 同目标已派未收 | 不重发；补要求就续派原会话，避免重复复制上下文 |

## 8. 上下文纪律

**只给**：当前目标与验收标准、必要的少量规则、涉及模块摘要、上一轮检查点、当前红线。

**不要给**：完整聊天史、全量 `docs/`、别人的在制文件与未提交内容、大 HTML 或长日志全文（用路径、行号、摘要）。

**传指针不传全文**：给路径与票号，不粘正文；结论回收只要摘要。上下文拥挤时先存检查点再按需检索，不要反复复制整份背景。

## 9. 静态自检

- 简单任务有没有被拆成多层？拆了就是过派。
- 每个子代理是否拿到了范围、权限、验收、交付四件？
- 并行写入的文件域是否真的不重叠？
- 回执里有没有可核对的证据？

## 10. 委派完成契约

- **最终消息就是交付物**：被派的一方不许以「等后台 agent」「等结果」结束回合——它交回来的必须是能直接用的结论。
- **谁派谁收**：派了就要自己核、自己整合、自己回；fire-and-forget 视为未完成。
- **但「收回合」≠「焊在原地干等」**：宿主在后台跑子代理时，回合结束是**唯一**能让回执进来的方式。
  所以派活方的义务不是「不许结束回合」，而是两条——① 结束前先把等待梯走到空档（能补位就补位、
  能现量下一张票就现量，见协议 §八）；② 确实只剩等时，**先落续跑指针**再收场，并写明「这不是完工，在等 X」。
  无指针的静默收口才算违例；有指针的等，是正常状态。
- **按需才拆**：单上下文装得下就不拆；拆了就要负责收口，不把结果孤儿留在后台。
