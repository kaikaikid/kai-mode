# 模型组框架（Magpie 子代理 · 角色 → 模型组 + 思考强度）

> 用法：每个角色一行，格式是 `group/tier-<档> <档名> —— <思考强度>`。
> `<档> <档名>` 是这一档的「模型组」（按能力分级的桶），`<思考强度>` 是该角色固定的推理档位。
> 子代理的模型**只能取这六个 `group/tier-*` 之一**，不接受其它 `group/*`。
> 校验：`python scripts/check-tiers.py`（角色↔档↔推理档↔成员能力↔`config.toml` 五方对账，漂移即红）。

## 2. 每组的硬约束（路由时逐条核对）

- **R 读档**：口径定为 `none`——池子本来就是纯闪池，好处是几乎不花钱，代价是别指望它做判断。真正要省的是派它的次数，不是它的单价。
- **C 编码档**：必须 `high`。`max` 已删（6 个成员只有 2 个支持，命中其余成员会静默降档且无提示）。
- **P 规划档**：必须 `high`；`xhigh`/`max` 同理删。要更强的思考只能单开一档、把不支持的成员切出去。
- **V 审查档**：只有 `high` 合法；可与 P 同池；必须能独立跑只读检查 / 测试取证。
- **G 图档**：必须 image 输入；池内 `ollama/qwen3.5:latest`、`opencode-zen-free/mimo-v2.6-flash-free`、`zhipu/glm-4.6v-flash` 无推理档，待按「image ∧ 支持 high」重挑。
- **W 宽页档**：真 1M；只「读得多」，不要求推理强、不要求会写；只在没有更细办法时用。
- **通用**：改任何一档的成员或合法推理档，先跑 `scripts/check-tiers.py`，别凭记忆。

## 4. 在 Magpie UI 里怎么填

1. 资源库 → 子代理：每个角色建一个，名字用第 0 节的英文名。
2. 模型：**不选**——magpie 的子代理卡片没有 model 字段，档位由派活时的 `模型：group/tier-X` 显式带过去。
3. 思考强度：同上，由 `推理：` 行带。父配置只留一个兜底值（见第 5 节）。
4. 沙盒：worker 唯一 `workspace-write`，其余 `read-only`（当前真机未强制，见第 5 节末）。
5. 指令：从 `喜鹊建表清单.md` 对应角色的「指令」块整段复制。
6. 路由页：确认六档 `group/tier-*` 的「支持推理档」与第 1 节一致。改完 magpie 会自动重下发 `magpie-models.json`（实测 01:55 生效，无需重启），跑 `scripts/check-tiers.py` 复核即可。

> 一个角色固定绑一档（静态映射命中 prompt cache，比每次动态选便宜）。窗口是限制手段不是省钱手段，不要为「宽一点舒服」升档。
