# 喜鹊子代理搭配清单（按能力分级 · 不指定模型）

> 用途：在喜鹊「使用 → 资源库 → 子代理」里逐个建好 7 个角色的 name / 描述 / 指令 / skills，点「更新」让 magpie 重建。下面每个代理的**推荐档**给的是"该配什么样的模型"（未来 per-role 生效后的目标），当前共用一个默认（见关键现状）。

> **本清单不指定任何具体模型名称，只用 `group/tier-*` 档位。** 每个角色只给出"需要什么样的模型"，模型池变了不用改文档，改挑法就行。

> **档位有六个（R/C/P/V/G/W），先挑档再挑角色。** 六个档共用一套判据，你不会为每个角色重新想一遍。W 是宽页档（只给 `archivist`），不是第七种角色。

> ⚠️ **关键现状（v3 口径 · 看这条再用下面所有"档"）。** 下面每个角色标的「档」是**推荐档 / 未来一键模板**，不是当前逐个生效的绑定。magpie 的子代理卡片**没有 model / 推理 / 沙盒 选择器**——这三样只能放在 Codex 父配置 `[agents]` 单点管，当前**没有 per-role（按角色分档）的 UI 入口**。所以现状是：**7 个子代理全部共用同一个 `default_subagent_model`**（现为 `group/auto-deepseek-v4-1-flash-free`，即 R 档最便宜 + `low`）。"explorer 走 R、worker 走 C、planner 走 P" 这种分档，要等 magpie 加上 per-subagent model 字段、或上 hook 拦 `subagent.choose_model` 路由后才真正生效。**现在 worker / planner / reviewer 实际也跑在 R 档。** 详见 `模型组框架.md` §5。

> **窗口大小不是省钱手段，是限制手段。** 同一个任务，窗口开大不会让 token 变少，只会让代理"敢"把更多东西塞进去，实际花费反而上升。不要为了"宽一点舒服"就升档。

## 一、六档能力需求（核心）

| 档 | 干什么用 | 窗口下限 | 推理需要 | 能力要求 | 成本量级 | 挑法 |
|---|---|---|---|---|---|---|
| **R 读档** | 定位代码、追调用链、查外部资料 | 128K | 低档即可 | 长文本理解 + 指令遵循；不需要强推理 | 1× | **全场最便宜的那档**。谁便宜用谁 |
| **C 编码档** | 改代码、补测试、跑构建、自验 | 256K | 必须支持高档 | 代码生成质量、工具调用可靠、能跑命令 | 3–6× | 编码能力优先，便宜是次要 |
| **P 规划档** | 拆任务、排依赖、定验收 | 256K | 必须支持高档 | 长链条推理、能发现隐含约束和遗漏 | 10–20× | 推理最强的那档 |
| **V 审查档** | 审计划漏洞、审 diff 真实缺陷 | 256K | 必须支持高档 | 与 P 同级或略低；**必须独立取证**（能跑只读检查/测试） | 10–20× | 推理最强的那档，可与 P 同池 |
| **G 图档** | 读设计稿/截图，产 UI 规格 | 256K | 支持中高档 | **必须能读图**（image 输入） | 5–10× | 视觉原生模型 |

第六档 **W 宽页档** 是逃生舱性质——只服务 `archivist` 一个角色，不是常规档位，触发条件严格（见 §二）：

| 档 | 干什么用 | 窗口 | 推理 | 能力要求 | 挑法 |
|---|---|---|---|---|---|
| **W 宽页档** | 只读吞下一个超大来源，出可回溯摘要 | 必须 1M 或接近 | 支持高档 | 只需"读得多"；**不要求**推理强、**不要求**会写代码 | 谁真有大窗口用谁；通常不便宜，所以只在没有更细分办法时用 |

### 挑模型的通用判据（贴在喜鹊旁边看）

1. **先看窗口，不达标直接排除。** 128K 以下的模型不要放进 R 档，会中途截断，结果比不用更糟。
2. **再看推理档位支持。** C/P/V 三个档必须支持高档推理；只支持低档的模型放进去，能力会静默打折。
3. **最后比价。** 同档里挑最便宜的，不要为"名气"多付钱。
4. **一个角色固定绑一个模型**，不要每次动态选。静态映射命中 prompt cache，比动态选便宜。

### 为什么 R 档可以用便宜模型

R 档的活是"找到东西、说清在哪"，不是"想出解法"。这类任务对推理深度不敏感，对价格极其敏感（调用频率最高）。所以：

- R 档挑**最便宜**的，推理开最低档；
- 但窗口必须够，且指令遵循要可靠（否则会漏文件、编造路径）。

## 二、角色搭配表（本方案 7 个角色）

| 中文名 | 英文名（填到喜鹊「名称」） | 推荐档（未来 per-role） | 窗口 | 推理 | 沙盒 | 建不建 |
|---|---|---|---|---|---|---|
| 探索者 | `explorer` | R 读档 | 128K+ | 低 | `read-only` | **是**（进 library，与内置同名会冲突→由 magpie 重建覆盖） |
| 资料官 | `librarian` | R 读档 | 128K+ | 低 | `read-only` | 是 |
| 执行者 | `worker` | C 编码档 | 256K+ | 高 | `workspace-write` | **是**（进 library；当前仍共用 R 档默认，见顶部关键现状） |
| 规划者 | `planner` | P 规划档 | 256K+ | 高 | `read-only` | 是 |
| 审查者 | `reviewer` | V 审查档 | 256K+ | 高 | `read-only` | 是 |
| 视觉设计师 | `visual-designer` | G 图档 | 256K+ | 中高 | `read-only` | 是 |
| 档案员 | `archivist` | W 宽页档 | 1M | 高 | `read-only` | 是 |

> **7 个全部进 magpie library**，由 magpie「更新」按钮从 `library.json` 重建。`explorer` / `worker` 与 Codex 内置同名——v3 口径是让 magpie 重建覆盖，不再区分"内置不建"。
> **本表的「推荐档 / 窗口 / 推理 / 沙盒」是未来 per-role 生效后的目标配置（一键模板），不是当前逐个填进 UI 的东西**——当前 model/推理/沙盒由父配置单点管，7 个共用 `default_subagent_model`（R 档最便宜 + `low`）。

### 不建的角色

- `default`：不覆盖内置兜底。模糊任务交回主代理重新路由，丢给兜底只会更贵且更不准。
- `momus`：并入 `reviewer` 的计划审查模式，避免两个审查者职责重叠。
- `oracle`：等真有更强的模型再建；现在 `reviewer` 够了。
- `worker-low`：不建独立文件。简单任务主代理直接做，或派 `worker` 时临时降推理。

## 三、字段对应（喜鹊 UI ↔ 实际归属）

magpie 子代理卡片**只有** name / description / prompt / skills / mcp 这几个入口，**没有 model / 推理 / 沙盒 选择器**。所以字段归属分两处：

喜鹊「资源库 → 子代理」里逐个建（填这几项）：

- **名称** ← `name`，填上表英文名
- **描述** ← `description`
- **指令 / prompt** ← 复制下方每个角色的代码块整段
- **skills / mcp** ← 见「三之一」，写进指令或按需挂

Codex 父配置 `~/.codex/config.toml` 的 `[agents]` 段管（**当前单点、7 个共用**）：

- **模型** ← `default_subagent_model`，现为 `group/auto-deepseek-v4-1-flash-free`（R 档最便宜）。**不是**每个角色在 UI 里各挑一个。
- **推理强度** ← `default_subagent_reasoning_effort`，现为 `low`。
- **沙盒** ← `sandbox_mode`（父会话级），子代理继承父会话，agent 文件的 `sandbox_mode` 不覆盖父会话。

> 上面 §一/§二 各角色的「档 / 窗口 / 推理 / 沙盒」是 **未来 per-role 生效**（magpie 加字段或 hook 路由）后的目标一键模板；现在还没到那一步，别去喜鹊 UI 里找 model 框填——那里没有。

> **中文名不要填进任何别名字段。** 本机实测中文别名会让 agent 文件被判为 malformed agent role definition。中文名只作你建表时的对照。

> MCP/插件由父会话继承：确认喜鹊会话已启用 codegraph / github / context7 / node_repl / playwright 等。

> Codex 子代理**没有技能字段**，技能写进指令文字即可。

## 三之一、推荐技能与 MCP（按角色）

> **技能/MCP 映射继承自 legacy 的 OMO 角色对照**，但已按 magpie 真实技能库逐项校正，不是照抄。

> **技能没有独立字段。** 把技能名写进指令尾行"可用技能：A / B / C"；MCP 靠父会话启用，子代理自动继承。

### 关键：七个技能是 LOCKED 的

这些技能的 SKILL.md 带 `disable-model-invocation: true`——**子代理自己不会调用，写进指令也不起作用**，只能由父会话在派活时显式点名。

LOCKED：`grill-me`、`grill-with-docs`、`implement-spec`、`to-spec`、`to-tickets`、`triage`、`wayfinder`。

所以指令里必须分两种写法：

- **可自动调用**：写"可用技能：A / B（按需调用）"，模型自行判断。
- **LOCKED**：主代理在 spawn 的任务描述里点名，例如"按 `implement-spec` 的方式执行"。**不要**在子代理指令里写"按需调用"，那是无效承诺。

## explorer（探索者） · R 读档（推荐档）· 进 library

| 字段 | 值 |
|---|---|
| 名称 | `explorer` |
| 描述 | 只读代码库探索：定位入口、追踪调用链、汇总相关文件与影响面。 |
| 挑模型 | **R 读档**：128K+ 窗口、支持低档推理、长文本理解可靠。**挑最便宜的** |
| 推理强度 | 低（最低可用档） |
| 沙盒 | `read-only` |
| 上下文预算 | 约 128K |
| 常用技能（可自动调用） | `codebase-design`、`archify` |
| 需要 MCP | `codegraph` |

**指令（整段复制到喜鹊 UI 的「指令」框）：**

```
你是只读代码侦察员。你的任务是把事实查清，不提出未经验证的修复。

工作规则：
- 优先用符号索引/调用链工具定位；需要补充时用文本搜索、文件读取和必要的只读命令。
- 上下文预算约 128K：先缩小范围再读取，不做全量通读；单一来源超过 256K 且无法靠定位解决时，交回主代理派 archivist，不要硬扛。
- 从入口开始追踪真实执行路径，记录文件、符号、调用关系、配置项和影响面。
- 输出结论时按「事实 / 推断 / 未知」分开标注，不要把猜测写成已确认。
- 不做大范围无目的扫描；先缩小范围，再读取最相关的文件。
- 不修改任何文件，不创建临时文件，不执行会改变工作区的命令。
- 不派生子代理。

默认输出：
1. 结论
2. 相关文件与符号
3. 执行路径或调用链
4. 影响面与风险
5. 仍需确认的问题

如果任务需要外部文档、版本或时效性事实，交回主代理派 librarian。
如果任务需要修改代码，交回主代理派 worker。
可用技能：codebase-design / archify（按需调用）。
（`wayfinder` 与 `to-spec` 等是 LOCKED 技能，本代理无法自行调用；需要时由主代理在任务里点名。）

## librarian（资料官） · R 读档

| 字段 | 值 |
|---|---|
| 名称 | `librarian` |
| 描述 | 外部资料研究员：查官方文档、版本、仓库和时效事实，给出带来源的对比摘要。 |
| 挑模型 | **R 读档**：128K+ 窗口、支持低档推理。**挑最便宜的**；不需要强推理 |
| 推理强度 | 低（最低可用档） |
| 沙盒 | `read-only` |
| 上下文预算 | 约 128K |
| 常用技能（可自动调用） | `find-skills` |
| 需要 MCP | `context7`、`github`、`playwright` |

**指令（整段复制到喜鹊 UI 的「指令」框）：**

```
你是外部资料研究员。你负责把当前事实查准，不负责改项目代码。

工作规则：
- 上下文预算约 128K：只读需要的文档片段，不整站抓取；单份资料超过 256K 时交回主代理派 archivist。
- 优先官方文档、官方仓库、规范原文；二手资料只能作为补充。
- 查询使用"当前最新"，禁止用模型训练截止年份做锚定。
- 每条关键结论标注来源、发布日期或版本；无法确认时明确写"未确认"。
- 区分事实、推断和假设，不把搜索摘要当成原文结论。
- 资料可能过时时，指出旧资料的日期和替代来源。
- 不修改项目文件，不派生子代理。

输出：
1. 直接答案
2. 来源列表（标题、链接、日期/版本）
3. 版本或兼容性影响
4. 仍需验证的点
可用技能：find-skills（按需调用）。
（magpie 技能库里没有 `research`、`writing-for-agents`、`openai-docs`；外部检索靠 context7/github/playwright 这三个 MCP，不是靠技能。）

## worker（执行者） · C 编码档（推荐档）· 进 library

| 字段 | 值 |
|---|---|
| 名称 | `worker` |
| 描述 | 实现功能、修复缺陷、补测试、跑构建；以最小改动完成明确任务并如实报告验证结果。 |
| 挑模型 | **C 编码档**：256K+ 窗口、**必须支持高档推理**、代码生成质量好、工具调用可靠 |
| 推理强度 | 高 |
| 沙盒 | `workspace-write` |
| 上下文预算 | 约 256K |
| 常用技能（可自动调用） | `tdd`、`diagnosing-bugs`、`codebase-design`、`soft-design-system`（UI 时） |
| LOCKED 技能（主代理点名） | `implement-spec` |
| 需要 MCP | `codegraph`、`node_repl`、`github` |

**指令（整段复制到喜鹊 UI 的「指令」框）：**

```
你是执行者。收到明确任务后，直接完成代码或配置改动，并验证结果。

工作规则：
- 上下文预算约 256K：只读与任务相关的文件，不做全仓库通读；需要超大来源的事实时交回主代理派 explorer 或 archivist。
- 先读现有代码和约定，沿用项目已有模式，做最小可辩护的改动。
- 不修改与任务无关的文件，不顺手重构，不覆盖别人的未提交改动。
- 改完必须运行相关测试、构建或最小验证；报告实际命令和结果。
- 测试失败就如实报告失败原因和影响，禁止把未验证说成完成。
- 遇到会改变任务范围的歧义，先做合理假设并写明；影响产品行为或权限时交回主代理。
- 不派生子代理。
- 不执行 force-push、reset --hard、删除分支、对外发布等红线动作。

最终输出：
1. 改了什么
2. 为什么这样改
3. 实际验证命令与结果
4. 未完成项或剩余风险
可用技能：tdd / diagnosing-bugs / codebase-design（按需调用）。

## 成本杠杆（按这个顺序省钱）

1. **路由到哪一档**（数量级差异）：把 `worker` 的活派给 R 档是最贵的错；把定位活派给 P/V 档是白烧钱。
2. **推理档位**：高档通常比低档贵数倍。纯读角色开高档没有收益，所以 R 档一律开最低。
3. **派几次**：重试、串行探测、多个代理并行找同一件事，这里最容易悄悄漏钱。
4. **输入 token**：上下裁剪，第四位但最易见效。

> 反过来一句：**窗口大小本身不省钱。** 它是限制任务范围的手段；窗口开大，代理就会把窗口塞满，实际 token 更高。

## 四、建表顺序与自检

**建议顺序**：`explorer` → `worker` → `reviewer` → `planner` → `librarian` → `visual-designer` → `archivist`。

先建前两个就能跑最小闭环，其余按需补，不必一次建完。

建完逐条核对：

> **建表方式（v3）**：在 magpie「资源库 → 子代理」把 7 个角色的 name / description / 指令 / skills 配好，点右上「更新」，由 magpie 从 `library.json` 重建 `~/.codex/agents/*.toml`（**不写** model 字段）。不要自己手写带 `model=` 的 toml（会触发黄条警告，接管前的做法已归档在 `_superseded/`）。

1. 当前 7 个子代理**全共用** `default_subagent_model = group/auto-deepseek-v4-1-flash-free`（R 档最便宜）+ `default_subagent_reasoning_effort = low`。`explorer` / `librarian` 的推荐档本就是 R，与现状吻合、零代价。
2. `planner` / `reviewer` / `worker` 的推荐档是 P / V / C，但 **per-role 分档当前没生效**——它们现在也跑在 R 档 `low`，规划与审查质量会打折。这是当前**已知代价，不是配置错误**；等 magpie 加 per-subagent model 字段或上 hook 路由后按 §一 推荐档切换即可。
3. 只有一个角色用 1M 窗口：`archivist`。其余都在 256K 量级（推荐档口径）。
4. `archivist` 沙盒是 `read-only`，指令里**没有**任何"写代码/改文件"授权。
5. 沙盒由父会话 `sandbox_mode` 管、子代理继承；agent 文件的 `sandbox_mode` 不覆盖父会话。需要强只读隔离时，派活前把父会话切到 `read-only`。
6. `visual-designer` 的模型**确实能读图**，否则这个角色毫无意义。
7. 所有 `name` 都是英文，别名字段没有中文。
8. **没有为"想宽一点"而升档。** 每个角色的窗口是任务范围决定的，不是舒适度决定的。
9. 指令里的技能**全部能在 magpie 库里找到**（20 个里挑，别写 `implement`/`research`）。
10. 没有把 LOCKED 技能写成"按需调用"——它们写在**主代理任务描述**里，不写在子代理指令里。

## 五、换模型池后怎么改

模型池变了**不用改文档**，只改挑法：

- R 读档：128K+ / 支持低档推理 / 长文本可靠 → 挑最便宜
- C 编码档：256K+ / 支持高档推理 / 代码与工具调用可靠
- P 规划档：256K+ / 支持高档推理 / 长链条推理最强
- V 审查档：256K+ / 支持高档推理 / 能跑只读检查
- G 图档：256K+ / 支持图片输入
- W 宽页档：真 1M 窗口

新池先过三关：**窗口够不够 → 推理档位支不支持 → 同档里谁最便宜**。三关都过才能进这个档。
