# 路由决策树

## 0. 先判断是否值得派活

满足任一条件，主代理可以直接完成，不派子代理：

- 任务只有一个明确的小改动，预计单文件完成；
- 用户只是问一个事实，主代理已有可靠来源；
- 任务是查看少量文件或单张图片；
- 子代理的启动、上下文复制和汇总成本高于任务本身。

否则按下表路由。

---

## 1. 主决策树

```text
任务开始
│
├─ 只需要定位/理解代码？
│  └─ 能定位 → explorer
│     单一来源超过 256K 且定位不了 → archivist（只出摘要，不做判断）
│
├─ 需要外部文档、版本或时效事实？
│  ├─ 只查资料 → librarian
│  └─ 查完还要实施 → librarian → planner/worker
│
├─ 需要 UI/视觉设计？
│  ├─ 只要设计规格/资产 → visual-designer
│  └─ 还要落代码 → visual-designer → worker
│
├─ 要改代码/配置？
│  ├─ 低风险、范围明确 → worker
│  ├─ 中高风险或跨模块 → planner → reviewer(计划) → worker → reviewer(diff)
│  └─ 已有明确计划 → worker → reviewer(diff)
│
└─ 以上都不匹配
   └─ 主代理重新判断，不默认派 default
```

---

## 2. 什么算中高风险

出现任一项，就按中高风险处理：

- 跨两个以上模块或服务；
- 改权限、认证、sandbox、密钥、数据库 schema；
- 改数据迁移、删除逻辑、回滚逻辑；
- 改公共 API、协议、持久化格式；
- 影响发布、部署、CI、hooks；
- 较大 UI/交互改版；
- 用户明确要求先出方案或先审查。

低风险示例：单文件文案、局部样式、明确的单测、配置默认值小改。

---

## 3. 计划审查的触发

`worker` 开始前必须经过 `reviewer` 计划审查，当且仅当：

- 任务属于中高风险；
- 计划包含 4 个以上有依赖的步骤；
- 计划需要新增或修改公共接口；
- 用户要求“先给方案再动手”。

不满足时，`planner` 可给出精简计划后直接交给 `worker`。

---

## 4. 并发与生命周期

- 读任务可以并行：`explorer`、`librarian`、`reviewer`。
- 写任务默认串行：同一时刻只允许一个 `worker` 改同一工作区。
- 不要并行派两个 `worker` 写相邻文件；需要拆分时按文件域拆，且由主代理合并。
- 并发上限使用 `agents.max_concurrent_threads_per_session = 3`。
- 派生深度锁死一层：`agents.max_depth = 1`。子代理不得再开子代理，路由权只在主代理。

### 收口三条（硬规则）

1. **必 close。** Codex 的并发额度按"尚未 close 的 agent"计数，不是按"正在跑的 agent"计数。任务交回后不 close，就等于一直占坑；本机额度只有 3，占满后表现为派不动。实测 2026-10-17～21 的 29 条 spawn 边里 16 条停在 open。
2. **同目标不重发。** 同一角色、同一目标、上一发结果尚未回收时，禁止再开一发；要补充要求就续派原会话。重发一份等于把同一件事的上下文重新复制一遍，是最大的隐性漏钱口。
3. **超时算未确认。** 到点没回音记 `unreconciled`，既不算完成也不算失败——先确认它是否还在跑，再决定续派还是关闭。把空转当 completed 是最危险的假绿。

---

## 5. 升级规则

| 情况 | 处理 |
|---|---|
| `explorer` 预算不够（R 档窗口 200K 装不下） | 先缩小范围重试；仍不行且是"范围散但可定位"，派多个 `explorer` 分头查 |
| 单一来源本身超过 256K 且无法定位 | 派 `archivist` 出可回溯摘要；**不要**为了省事给 `worker` 开宽窗 |
| 任务需要同时放长草稿和大量参考 | 让 `librarian`/`explorer` 先压缩材料，再进 `worker`；不要把参考原样堆给写手 |
| `worker` 连续两次失败 | 交回主代理；让 `reviewer` 或 `planner` 重新分析，不盲目重试 |
| 出现外部版本不确定性 | 派 `librarian`，不要猜 |
| 需要视觉判断 | 少量图主代理自己看；设计生产派 `visual-designer` |
| 任务范围失控 | 停止派活，交回用户确认边界 |

---

## 6. 禁止路由

- 不因为“任务模糊”就派 `default`；
- 不让 `worker` 自己找 `reviewer` 或再派代理；
- 不让 `reviewer` 边审边改；
- 不让 `visual-designer` 直接改业务代码；
- 不让 `explorer` 用“顺便修一下”扩大任务。
