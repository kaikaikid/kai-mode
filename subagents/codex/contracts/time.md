# 时间与时效事实契约

## 1. 原则

模型记忆可能过期。凡是会随时间变化的事实，都不能直接凭记忆回答。

典型包括：

- 软件版本、依赖版本、API 变更；
- 模型发布、价格、限额；
- 政策、条款、可用地区；
- 赛事、人事、新闻；
- 第三方服务的当前行为。

---

## 2. 父会话注入

主代理在派活前提供当前日期和时区，例如：

```text
当前日期：2026-10-18（Asia/Shanghai）。
对时效事实先查当前来源，不要用训练截止年份做锚定。
```

日期由运行环境提供，不写死在代理 TOML 里。

---

## 3. 角色约束

### librarian

- 查询使用“当前最新”“截至今天”等相对表达；
- 禁止“2025 年最新”这类旧年份锚定；
- 每条关键结论给出来源和发布日期/版本；
- 旧资料标注“可能过时”，并优先找更新来源。

### planner

- 涉及依赖、版本、外部 API 时，标记为“待核实”；
- 不把模型记忆中的版本号写进计划；
- 需要事实时交回主代理派 `librarian`。

### reviewer

- 审查版本相关改动时，要求提供来源或当前验证；
- 不因为“看起来是最新版”就放过兼容性风险。

### explorer

- 读取项目内锁文件、配置或文档时，记录版本和日期；
- 只报告项目事实，不推断外部最新版。

### worker

- 不自行升级依赖版本，除非任务明确要求；
- 需要选版本时，使用项目锁定版本或让 `librarian` 核实。

---

## 4. 验收测试

向 `librarian` 提一个当前版本问题，检查：

1. 查询里是否出现旧年份锚定；
2. 是否给出发布日期或版本；
3. 是否区分官方来源和二手来源；
4. 是否明确标注无法确认的部分。

任一项不满足，时间契约未通过。
