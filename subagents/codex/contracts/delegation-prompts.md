# 可直接使用的派活模板

主代理复制模板后，只替换尖括号中的内容。**`模型：` 和 `推理：` 两行是必填，照抄不改**——它们决定这一刀跑在哪个档上，漏写就掉到父配置兜底（C 档 + high），那是保险丝不是常规路径。

档位取值（2026-10-23 实测成员交集后的合法值，不要自作主张改）：

| 角色 | 模型 | 推理 |
|---|---|---|
| explorer | `group/tier-r` | `none` |
| librarian | `group/tier-r` | `none` |
| worker | `group/tier-c` | `high` |
| planner | `group/tier-p` | `high` |
| reviewer | `group/tier-v` | `high` |
| visual-designer | `group/tier-g` | `high`（池子待重挑，见 roles.yaml caveat） |
| archivist | `group/tier-w` | `high` |

## explorer

```text
角色：explorer
模型：group/tier-r
推理：none
目标：查清 <行为/符号/错误> 的入口、调用链和影响面。
范围：只读 <目录/模块>。不要修改任何文件。
输入：<已知现象、相关文件、最近改动>。当前日期：<YYYY-MM-DD>。
验收：至少给出入口文件、关键符号、调用路径、影响面和未知项。
输出：结论 → 证据路径 → 调用链 → 风险 → 未知项。
收尾：交出结论后立即 close。
```

## planner

```text
角色：planner
模型：group/tier-p
推理：high
目标：为 <目标> 产出可执行计划。
范围：只读 <目录/模块>，不写代码。
约束：非目标 <...>；风险级别 <低/中/高>；不要凭记忆写版本号。
输入：<需求、已知事实、相关文件、当前日期>。
验收：每步有依赖、涉及文件/模块、风险、可观察完成条件。
输出：目标/非目标 → 假设 → 分步计划 → 风险 → 验收标准 → 待拍板问题。
收尾：交出计划后立即 close。
```

## reviewer（计划审查）

```text
角色：reviewer
模式：plan_review
模型：group/tier-v
推理：high
目标：审查下面的计划是否存在遗漏、依赖错误、不可验证步骤或高风险。
范围：只读；不修改计划文件，不写代码。
输入：<完整计划>。
验收：问题按严重程度排序；没有阻断问题时明确说明，并列出剩余假设。
输出：严重程度 → 问题 → 触发条件 → 修正建议。
收尾：交出结论后立即 close。
```

## worker

```text
角色：worker
模型：group/tier-c
推理：high
目标：实现 <明确结果>。
范围：只改 <文件/目录>；不要碰 <禁区>。
约束：遵循 <项目约定>；不做无关重构；不执行红线条目。
输入：<计划或规格、相关文件、当前日期>。
验收：<测试/构建命令> 通过；失败必须如实报告；给出 diff 摘要。
输出：改了什么 → 为什么 → 验证命令与结果 → 剩余风险。
收尾：自验通过后 close；需要返工时续派原会话，不要重开。
```

## reviewer（代码审查）

```text
角色：reviewer
模式：code_review
模型：group/tier-v
推理：high
目标：独立审查 <分支/commit/工作区> 相对 <基线> 的 diff。
范围：只读；可以运行只读检查和测试，不修改文件。
关注：正确性、边界条件、安全、行为回归、缺失测试、项目约定。
输入：<任务目标、diff 基线、相关 issue/规格>。
验收：先报 findings，按严重程度排序，附文件和行号；没有问题时明确说明。
输出：findings → 复现条件 → 建议修复 → 剩余风险。
收尾：交出 findings 后立即 close。
```

## librarian

```text
角色：librarian
模型：group/tier-r
推理：none
目标：确认 <库/API/版本/政策> 的当前事实。
范围：只读外部资料，不改项目文件。
约束：当前日期 <YYYY-MM-DD>；用“当前最新”查询，禁止用旧年份锚定。
验收：关键结论有官方来源、发布日期或版本；区分事实、推断、未确认。
输出：直接答案 → 来源 → 版本/兼容性影响 → 待确认项。
收尾：交出来源后立即 close。
```

## visual-designer

```text
角色：visual-designer
模型：group/tier-g
推理：high
目标：为 <页面/组件> 产出 <设计规格/布局/视觉资产>。
范围：只读现有设计系统和参考图，不改业务代码。
约束：遵循 <设计系统/品牌规范>；适配 <桌面/移动>；说明状态和交互。
输入：<截图、现有页面、目标用户、断点>。
验收：布局、token、组件、状态、响应式行为均可执行；不确定项明确列出。
输出：设计结论 → 布局 → 组件/token → 状态与交互 → 移动端 → 待确认。
收尾：交出规格后立即 close。
```

## archivist（条件代理，别默认派）

触发条件只有一个：**单一来源超过 256K，且 rg / codegraph / 局部读取都定位不了**。不满足就别派它——它能读全量不代表该读全量。

```text
角色：archivist
模型：group/tier-w
推理：high
目标：把 <超大单一来源> 压成可回溯摘要。
范围：只读 <文件/目录>，不修改、不创建文件。
输入：<来源路径与规模、这次要回答的具体问题>。
验收：写明实际读取了输入的百分之几、跳过了哪些部分；引用保留路径 + 行号或节名；不把未读部分说成已读。
输出：来源与规模 → 已确认事实 → 推断与不确定性 → 未覆盖部分与建议的精读定位。
收尾：交出摘要后立即 close。
```

## 收口三条（对所有角色生效）

1. **必 close**：任务交回后立刻关闭子代理。Codex 的并发额度按"未 close 的 agent"计数（本机上限 3），留着不关等于占坑，症状是后面派不动。
2. **同目标不重发**：同一角色、同一目标、上一发还没回收结果时，禁止再开一发；要补充要求就续派原会话。
3. **超时算未确认**：到点没回音记 `unreconciled`，不得当作完成，也不得直接判失败重派——先查它是不是还在跑。
