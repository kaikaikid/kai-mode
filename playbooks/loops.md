# 三循环（治理 · 执行 · 反馈维护）

> V1.0 设计基线 §三的吸收。三个循环**共享状态，不共享无限增长的对话历史**。
> 每个循环都是“有限轮次、每轮完成即退出、下次重新唤醒”，不是一个永不退出的 AI 会话。

## 循环总表

| 循环 | 谁跑 | 触发 | 产出 | 终止条件 |
|---|---|---|---|---|
| A 任务治理 | Tower | 用户规划、票面变化、周期巡检 | 可执行队列、合同补齐、新票/拆分 | 队列满水位或没有可开的票 |
| B 任务执行 | Group → Ground | 存在 Ready 且未锁的票 | 本地提交、验收证据、落地/关闭 | 票关闭、阻塞、失败 |
| C 反馈维护 | Coordinator / Group | 测试失败、审查意见、超时、崩溃、巡检 | 新尝试、阻塞、后续票 | 修复成功或达到上限 |

## Loop A：任务治理

**目标：让队列里的每张票都“可被一个陌生执行器独立理解并开工”。**

1. 读已授权队列与 `plan.json` 顺序层。
2. 逐票检查任务合同十字段（`playbooks/task-contract.md`）；缺项 ⇒ 补合同或退回 Backlog，不进 Ready。
3. 检查前置依赖：依赖未关闭 ⇒ 标 `blocked`，不排；依赖已关闭但未验证 ⇒ 先验证再排。
4. 大票拆成可独立验收的子票；子票必须各自有 AC、文件域、验证命令。
5. 检查是否有遗漏的后续工作；只有**有证据、有父票、过 DoR** 的后续才开新票。
6. 架构争议、需求冲突、高风险决策 ⇒ 进签派单等人，不自行拍板。

**反无限生成（硬规则）：**

- 每个新票必须有父票或用户原话/证据；没有就写进日报，不开票。
- 同一父票一次最多开 3 张后续票；要更多先问用户。
- 不允许为了“队列看起来有进展”而开没有验收标准的票。
- 新方向票不自开；机械票（解封、拆刀、补账、清账）可自开。

## Loop B：任务执行

1. Tower 发队列＋逐票租约，票状态 `ready → claimed`。
2. Group 检查租约、工作树、marker，状态 `claimed → running`。
3. 组内派 Researcher / Implementer / Reviewer（按需；简单票可只用一个执行器）。
4. 实现、测试、记录检查点；实现完成 ⇒ `running → validating`。
5. Reviewer 逐条 AC 判；不过且可修 ⇒ `validating → repairing`；过 ⇒ `validating → ship_ready`。
6. Group 给 Ground 发 ship handoff；Ground 验门、并车、push/PR、`ship_ready → landed`。
7. close-gate 通过、票面留证、关闭 ⇒ `landed → closed`。
8. Ground 给 Tower 发补排班 handoff；Tower 进入下一轮 Loop A。

**边界：** Group 不并车、不 push、不排班；Ground 不写实现；Tower 不写产品代码。

## Loop C：反馈与维护

**触发：** 测试失败、reviewer 判不过、PR 意见、执行超时、进程崩溃、周期巡检。

1. 收集失败事实：失败命令、完整输出、提交号、检查点、复现步骤。
2. 分类：
   - 可自动修：同一租约内、原因明确、不超过尝试上限；
   - 需人决策：需求冲突、高风险、权限/凭据、对外发布、不可逆；
   - 环境/外部：依赖缺失、网络、宿主能力 ⇒ 记 `blocked` 并点名缺什么。
3. 在**新的尝试**里恢复：新上下文、同一票、新 attempt 号；不复用坏掉的会话。
4. 修复最多 3 轮；**同一错误签名出现 2 次 ⇒ 提前停**（见 `reliability.md`）。
5. 每轮重跑定向测试；必要时跑完整验收。
6. 到上限 ⇒ `failed` 或 `blocked`，留证据、通知用户；已确认的缺陷开后续票。
7. 连续 3 次启动失败/门红 ⇒ 熔断，写 `hold-<role>`，等用户或 Coordinator 处理。

**不允许：** 无限重试、静默跳过失败测试、把“模型认为修好了”当通过、用同一会话反复试到上下文爆炸。

## 共享状态

三个循环都读写同一套状态：

- 票面：GitHub Issue（内容与耐久状态）
- 顺序：`plan.json`
- 运行态：`task-state-<票>.json`（细状态、尝试、租约、检查点指针）
- 事件：`events.jsonl`（只追加，不去改历史）
- 交接：`handoff-*.json`（≤500 B 指针）
- 验收：`acceptance-<票>.json`（逐条 AC 证据）

**冲突对账顺序：** git 事实 > GitHub 票面 > 本机状态/事件 > 聊天记忆。任何角色发现不一致，先停手写 `blocked`，不自行覆盖别人的账。
