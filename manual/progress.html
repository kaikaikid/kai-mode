kai-mode使用手册

日常

看进度

不要问“做完了吗”。去看三个地方：Issue 说状态，日表说谁在跑，看板把两者画成一张图。

三个地方，各看什么

Issue：现在是什么状态

每张票的评论里会写：开工、施工完成、审查完成、待发货、卡点。这是唯一事实源。

日表：谁在飞

主道、副道、二副道三张正常日表由塔台写；王牌写自己的加急日表。票进日表就算被领取。

看板：一眼看全

看板把票、日表、交接和 Issue 汇总成一页；列就是阶段，另有“待发货”队列和塔台灯。

想直接问一句

对 AI 说：“看现在在飞什么。” 或者用口令 /航班信息。它会读看板数据，告诉你哪些在飞、哪些待发货、哪里卡住。

“待发货”是什么意思

施工和审查都过了，但塔台还没合并、推送、关票。票在这一格时，机长的名额已经释放，可以继续拿下一张；只有塔台还没发。

看板是怎么更新的

  • 每次提交或合并，git 钩子会打一个“脏”标记。
  • 一个 30 分钟的定时器会把脏数据重新采集、落库、出页面；页面自己也会定时刷新。
  • GitHub 那边有更新时，--max-age 会兜底重拉。
  • 任何一个来源失败，只在页面上点名，不会让整页崩掉。
给技术同事：看板的数据与产物

一块板 ＝ 一个 SQLite 库 ＋ 一份板配置 ＋ 两个产物。配置在 board.config.json，必填 name、output.root、sources[]、stages[]、stage_rules[]；stage_rules 按顺序取第一条命中，最后必须是 else。

产物在 <output.root>/<板名>/：board.db、board.json（AI 只读，≤25KB）、index.html（人读）。展示层只读各源，不改票面、不改日表、不写回卡片。

模块依赖是单向的：db / stage / sources / collect / render / config；加一个源＝在 sources/ 放一个模块并在 REGISTRY 加一行。

技能正本：board/skills/flight-info/SKILL.md；命令：/refresh。
