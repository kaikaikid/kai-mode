kai-mode使用手册

日常

遇到问题

先记住一条：这套东西宁可说“缺”，也不会假装装好。看到“缺件”“卡点”“no-new-context”，不是坏了，是它在如实报告。

AI 说“缺件”

缺件会按三格写：缺什么 / 卡在哪 / 要谁拍。机器只认最后一行 missing: <kind>，其余是给人看的。

  • 缺什么：一句话说清，比如“没有定时器”“起不了新上下文”“只有软权限”。
  • 卡在哪：具体到探测的那一步或命令报错。
  • 要谁拍：人、换宿主、还是接受软约束。

不要让它猜一个路径继续跑。缺件登记本身不算修好；补法走 /set-kai-mode 的缺口清单。

装完技能没出现

  • 先确认你问的是同一个宿主：在 Claude Code 里装的，不会自动出现在 Qoder 里。
  • 看回执里的落点：技能应该在宿主的技能目录，或中央库链接到宿主。
  • 落点必须是项目级，不要装全局，避免和别的框架同名打架。
  • 还是看不到，就让 AI 重新扫描一次缺什么，不要手动复制正文改来改去——两份会漂移。

没有自动轮巡

这是设计如此：机场体系下线后不再有 60 分钟唤醒定时器，也没有塔台轮巡。用户按需起会话；施工由 coding jump 起子会话。

  • 每 60 分钟一轮；宿主不支持定时器时，回执会写“没装上”。
  • 门卫会先判断：上一轮还在跑、或者没活，就直接跳过，零模型调用。所以“没动静”可能是没活。
  • 要看进度，直接问舰桥或跑 coding status；不要自己改宿主定时任务。

票卡住了 / 失败了

单票失败会重试一次；再失败就写“卡点”停票，并说明原因。同一类错误连续出现会触发熔断。红线只停那一张票，不会拖垮整条线。

审查说“起不了新上下文”

审查必须换一段新上下文，不能施工的人自己审自己。宿主起不了子代理、独立进程或新会话时，会登记 no-new-context，并且不许记“已审查”。换一个能起新上下文的宿主，或先停下来问人。

“体检红了”

框架仓的红线是：python scripts/doctor.py 红了不许收工。总结行会写多少项、几绿几红；红了先修，不要绕过。项目仓那份配置实例用 check-instance.py 对账。

红线：唯一需要“停下来问人”的五件事

红线包括什么
花钱付费执行器、云资源、第三方服务
对外发布部署、发布、公开发帖、发邮件
不可逆改历史、force-push、数据迁移、破坏性改表、改权限 / 安全边界
删未提交的东西任何人的未提交文件、工作树、日志
把开发数据提交进仓库会话、日志、DB、缓存、验证报告、agent 数据、仓库自己的 handoff 记录

碰到红线时，正确说法是：“这张票停了，原因是……；需要你拍板：……”。不要先改审批规则或自己的权限，再自己批准。

最后一条

如果你不确定一件事算不算红线，就按红线处理，先问。停下来问一句的成本，远低于不可逆地做错一次。

给技术同事：缺件类型与自检命令

缺件类型：no-launcher · no-new-context · no-timer · no-model-field · soft-permission-only · paid-not-authorized · launch-failed · missing-instance。

框架仓：python scripts/doctor.py [--with-tests]；项目实例：python scripts/check-instance.py --repo <项目仓>；插件清单：python scripts/plugin-check.py；外部素材对账：python scripts/source-check.py。

run 状态与子会话日志：.coding/runs/<run>/；状态与 git 对账跑 coding doctor。探测失败要如实报错，不等于零活。

路径一律相对仓库根，不写盘符绝对路径；技能落点必须项目级。
