kai-mode使用手册

上手

一句话，变成一张有人负责的票

kai-mode 是一套“接活、排班、施工、审查、发货”的分工办法。你只需要说清楚想要什么；谁来做、谁来查、什么时候该你拍板，它都写好了。

先说清楚

你不需要懂代码，也不需要记住每个角色。你只要会描述想要的东西，并在“要花钱、要对外发布、要删东西”这类红线前停下来问一句。

它替你解决三件麻烦事

想法不会停在聊天里

一句话会被整理成一张票：目标、验收标准、允许改什么、禁止改什么、怎么验证。

干活和检查不是同一个人

施工的人只负责改；审查的人用新的上下文独立判断，只出“过 / 不过”和逐条证据。

做完有记录，换人也能接

状态写在 Issue 与 .coding/runs/ 里，代码在分支里；换人接手照这两样续跑。

谁把活交给谁

你只跟舰桥说话：它把需求整理成票、开 run、派子会话施工与独立审查，最后统一发货。中间任何一步卡住，只停当前 run，不会把整条线拖垮。

第一次用，按这个顺序

  1. 先装好

    把一句安装的话发给你的 AI，让它先扫描缺什么、只装缺的。去装好它 →

  2. 再开一张小票

    拿一件很小的事试一遍，走完“开票 → 施工 → 审查 → 发货”。看怎么开票 →

  3. 最后学看进度

    知道去 Issue、coding status 和看板哪里看“现在在跑什么”。去看进度 →

一个判断

如果一件事会花钱、会对外发布、会不可逆地改东西，或者要删别人还没提交的工作——先停，问人。这是整套办法里唯一的“硬停”。
