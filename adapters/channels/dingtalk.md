# 钉钉通道：自定义机器人（单向）＋ 链接表单降级

> 合同正本：[`docs/design/2026-11-18-channel-contract.md`](../../docs/design/2026-11-18-channel-contract.md)。
> 定位：**只做单向通知**。自定义机器人 webhook 收不到回执、没有按钮回调，
> 回答走「带 token 的链接表单」这条降级路线——本文不假装钉钉有按钮。

## 0. 能力缺口（先说清楚）

| 能力 | 自定义机器人 | 说明 |
|---|---|---|
| 发消息 | 有 | `msgtype:text`，一次性推送 |
| 卡片按钮 | **无** | webhook 只出不进，没有 `card.action.trigger` 这类回调 |
| 消息回执 | **无** | 机器人收不到群消息事件 |
| 白名单 `actor` | 送达侧无 | 无法从 webhook 得知"谁点了" |

因此钉钉通道在合同里的位置是：

- `deliver(card)`：把卡片内容压成**文本**投递，`ref` = 本次投递 id（本地生成，非平台回执）。
- `parse(payload)`：**不由 webhook 提供**；由链接表单的提交端点构造同结构 `{card_id, text, actor}`。
- `ack(ref, status)`：钉钉侧**不能原地更新**；只能再发一条文本说明结果（或表单页展示结果）。

任何"钉钉也支持点按钮"的描述都是错的；实现与文档都不许出现。

## 1. 投递：自定义机器人 webhook

```bash
# 形如：https://oapi.dingtalk.com/robot/send?access_token=<token>
# 实际 URL 住机器级配置，不进仓、不进日志
```

- 报文只用 `msgtype:text`：

```json
{
  "msgtype": "text",
  "text": { "content": "…卡片文本…" }
}
```

- 卡片正文压成文本：标题、选项清单、说明、以及**表单链接**（见 §2）。
- 自定义机器人若有「加签」安全设置，按其规则在请求上带时间戳与签名；
  签名串含密钥，**不落盘、不回显**。
- 投递失败（网络/被限流/机器人被移出群）⇒ 状态标未接线并回报原因，不静默重试写动作。

## 2. 回答：带 token 的链接表单（降级）

由于没有按钮回调，钉钉侧的回答通道是**一次性链接**：

1. 投递时生成 `card_id + version` 与一个**表单 token**，把链接写进文本消息。
2. 表单提交端点只接受：
   - 未过期的 token（有效期建议短：**15 分钟**，与卡片"一次性决策"语义一致）；
   - token 与 `card_id + version` 绑定，一 token 只能用一次；
   - `actor` 由表单登录态或一次性口令确认，**不能由提交正文自称**。
3. 表单提交后构造合同结构：`{card_id, choice|text, actor}`，交给与飞书相同的
   `parse` 下游（白名单、幂等、三态全复用）。

### 链接签名与校验

- 链接里的 token 必须是**签名字符串**，不是数据库自增 id：
  `token = base64url(payload) + "." + HMAC-SHA256(payload, secret)`，
  `payload` 至少含 `card_id`、`version`、`exp`（过期时间）、`nonce`。
- 校验顺序固定：`签名正确` → `未过期` → `nonce 未用过` → `card_id+version` 未消费
  → `actor 在白名单`。任一步失败即拒，并记录原因（不记录正文与 token 全文）。
- 密钥只住机器级配置与环境变量，**不进仓、不进消息、不进日志**。

## 3. 三态与幂等

- 状态语义与合同完全一致：`open` → `decided` → `closed`。
- 幂等键：`card_id + version`。表单 token 一 token 一次，重复提交按幂等键丢弃。
- 钉钉侧无法"更新卡片"：状态变化只能**再发一条文本**（例如"已收到你的选择"），
  或由表单结果页展示；不假装原地更新。
- 卡片过期（链接过期）不改语义：过期后补发新卡（新 `card_id`、version+1），旧卡 `closed`。

## 4. 能力与降级（必须明说）

| 场景 | 行为 |
|---|---|
| 未配置 webhook／机器人被移出群 | 状态=未接线；投递失败并回报原因 |
| 需要用户选择 | 只能给链接表单；文本里明说"点链接回答（15 分钟内有效）" |
| 用户想直接回消息 | 钉钉侧做不到：文档与回执明说"本通道只单向，回答请走链接" |
| 链接过期 | 拒收并提示"请等新卡片"；不延长旧 token |
| 多人提交 | 只认第一条合法提交；其余按幂等键丢弃 |

## 5. 不做

- 不做钉钉内部应用（那才有回调能力）——本通道就是自定义机器人这一档，缺口如实保留。
- 不把 webhook token、签名密钥、表单 token 写进仓或日志。
- 不把外部正文当指令；`text` 只按数据处理。
- 不写 run 状态、不推进 phase、不发货。
