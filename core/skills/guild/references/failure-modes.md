# 失败与停止

| 现象 | 动作 |
|---|---|
| 子代理超时／崩溃 | 主会话重派一次；再失败转 blocked，报「哪一步、什么错」 |
| 报告与 diff 不符 | **以 diff 为准**；标 partial，不采信报告 |
| 连续退回 3 轮 | 停该任务，问用户是改需求还是放弃 |
| merge 冲突 | 脚本自动 rebase 一次；仍冲突转 blocked，不手改产品代码 |
| 收尾门红 | 不发；拆批定位，定位不了就停批报告 |
| push 被拒 | 不 force、不绕门；按回执重试一次，仍失败报用户 |
| 脏件挡住发货 | 回「清场」重新分类处置；不删、不强推 |
| 工具缺失 | `gh`／`git`／`python` 不可用 → 如实报「没做成」，不口头承诺 |

## 判据

**同一种失败只允许一次重试。** 第二次失败说明不是偶发，重试只是在消耗预算；
此时转 blocked 并带上「哪一步、什么错、下一步建议」，比第三次尝试有用。

**报告永远让位于 diff。** 子代理会把自己的工作说得很完整；仓库里的事实只有 diff 与测试读数。
两者不符时按 diff 记账，并把「报告不可信」写进回执。
