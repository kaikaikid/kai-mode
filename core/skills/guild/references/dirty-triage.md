# 脏件分类与处置

主树有**已跟踪**脏件时，执行内核拒绝发货。先分类，再处置——每类只做一件事。

| 类别 | 判据 | 动作 |
|---|---|---|
| **记录件** | `.coding/`、`.ai/`、`handoff/`、日志、DB、缓存、构建产物 | 不碰、不提交、不阻塞 |
| **任务自身在制** | 用户说「接着改这个」，脏件就是本次要做的东西 | `fleet adopt <issue>` 接管为 baseline |
| **无关产品改动** | 已跟踪、不属于本次任务 | `fleet park -m "为什么收起"`；只收产品件，留 stash 回执 |
| **未跟踪用户数据** | `??` 开头 | 不碰；发货不拦未跟踪件 |
| **拿不准** | 分不清归属 | 问一次：保留为任务基础／先收起／不动；推荐第一项 |

## 绝对禁止

`git checkout --`、`git restore`、`git clean`、`git stash drop`、强推、删分支。

这些都会不可逆地吃掉别人的在制品。收起是可逆动作，删除不是。

## 回执

每次处置留一行：**路径 · stash ref · 恢复命令**（`git stash apply <ref>`）。
放回用 `fleet unpark <ref>`；不确定时先 `fleet unpark --list` 看清单。

## 为什么发货前必须清

内核只对**已跟踪**文件判脏：它要保证「这个 run 的产出干净可合并」。
记录件与未跟踪件不参与合并，所以不算阻塞；已跟踪的无关改动会被误带进合并，所以必须收起或接管。
