# staff —— 参谋部（规划与拷问方法）

> **不是入口**：对外只有康娜一个对话面。康娜遇到「需求大、方向未定、多方取舍」时调用本方法，
> 康娜在「判断走哪条」时自动调它；用户不需要记本技能的名字。
> 规划完把结果交回康娜去开票、开 run。

## 什么时候用

- 用户一句话说不清要什么，或方案有明显分叉。
- 一次要改多个模块、跨里程碑，或会动数据 / 权限 / 外部接口。
- 用户明确说「先规划」「想清楚再做」「别急着写代码」。

小修、单文件、需求清楚 → 不用本方法，康娜直接做。

## 方法（五步，一次一问）

1. **判断**：新想法 / 熟活 / 已有票。已有票先读票面，不重开。
2. **拷问 ≤5 问**：只问大方向，每题给 2–3 个选项，推荐项排第一并写一句理由。
   判据见 `../principles/SKILL.md`（§1 一次一问）。
3. **定稿**：
   - 清账：被推翻的旧决策、重复票、超 30 天没动的票——只列清单交用户，不自动关。
   - 术语与 ADR：影响长期结构的决定写成 ADR；方法用中央库原版 `domain-modeling`。
   - 拆票草案：按垂直切片拆成可执行工单（目标、AC、允许/禁止修改、验证命令）。
     **先判合并**：touchset 重叠且串行依赖的票默认合成一张票、多 AC；拆票只允许
     「能并行 / 能独立发货 / 风险隔离」三种理由。
     方法用中央库原版 `to-tickets`。**只出草案，开票归康娜。**
4. **规划表**：把「做什么 / 不做什么 / 先后 / 验收」汇成一张表。用户只在规划表上拍一次板。
5. **交回康娜**：拍板后，康娜开票并决定是否 `/jump` 开工。本方法不写代码、不开票、不 push。

## 审批边界

- 只拿肉眼可见的表象（界面、文案、交互、观感）与红线问人；看不见的技术细节自决并记一行理由。
  判据见 `../principles/SKILL.md`（§2 只问可见与红线）。
- 红线（花钱、对外发布、不可逆、删未提交内容）先停，不靠规划绕过。

## 输出

- 一张规划表（结论先行，可直接贴进 Issue）。
- 0–N 张拆票草案（六件套齐全；每张标并行/合并判断与并行宽度）。
- 一段给康娜的交接：先做哪张、依赖什么、哪一步需要用户再拍板。
