# 一个语义一个家

> 病征：旧体系的病就是同一件事有多份互相矛盾的正本。

## 何时进场

- 写或改任何技能、文档、配置，正要写下一条判据时。
- 发现同一判据两处说法不一样（配置面漂移）。
- 想把别处的规则「抄一份过来方便看」时。

## 判据

- **一个语义只许一个家**：每条判据有唯一正本（ADR / 技能叶子 / 脚本 / 注册表），完整、自足、可触发。
- **写第二条同义判据前，先问「第一条住哪」**：已有家 ⇒ 原处只留「流程位＋指针」；没家 ⇒ 先安家（ADR 或叶子），再放指针。
- **指针可多处，判据只一处**：流程位、一行索引、frontmatter 触发词都不算第二本。
- 改判据＝只改正本一处，改完跑正本声明的验证，读数进票面。
- 项目配置实例不是判据的家：实例只装「这个项目里它们落在哪、跑在什么上」。

## 反例

- 入口、角色、协议各写一遍红线——三本正本迟早打架；入口只留指针。
- 「为方便」把 ADR 判据整段抄进技能正文——抄本先腐烂。
- 两处说法相近、各改各的——漂移起点，回正本对表。
- 把判据写进项目配置实例——实例不装判据。

## 验证

- 任选判据关键词 grep 全仓：完整详述只命中正本一处，其余是指针。
