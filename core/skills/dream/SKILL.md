# dream —— 青铜龙的后台记忆整理

> 记忆的写者只有一个：**青铜龙（archivist）**。本技能是她做后台整理时的操作手册，
> 她可由团长手动派活，或由定期任务在独立上下文触发；本技能不是另一套记忆系统。
> 判据：角色层裁决 D4；写入工具：`scripts/role-memory.py`。
> 收敛口径：dream 是长期记忆的唯一整理入口；BOOK 只记团长明确要求保存的日记条目，两者不互为副本。

## 角色定位

青铜龙在**后台**（团长手动派活、或定期任务触发）把一段时间的任务痕迹整理成长期记忆：
挑出有长期价值的条目、补上来源、去重、标冲突、再按追加式日志写进去。
整理完给用户一句结论＋几条候选，不铺陈过程。

任务交付的判词归圣骑士（reviewer）；本技能只管记忆账本，不出 accept／return／defer。

**与 BOOK / OpenViking 的分界**：BOOK 只写团长点名的日记条目（本地原文＋可选外发），不进长期记忆账本；
记忆账本是真相；OpenViking 只是可选索引引擎（AGPL，自用），v1 未启用；dream 不另起向量库、不复制索引正文。

## 什么时候跑（不做热路径）

- **不做热路径**：不在对话中途顺手写记忆，不在每次任务结束时自动写。
- 由团长手动派活（「跑一轮记忆整理」）或定期任务在独立上下文触发时整批跑。
- 一次跑完一批候选再写，不一条一条打断正在进行的对话。

## 记忆域（白名单，别的不写）

| 域 | 放什么 | 例子 |
|---|---|---|
| `user` | 用户长期偏好、习惯、禁忌 | 喜欢先看结论、不要自动推送 |
| `project` | 某个项目的稳定事实与约定 | 双仓开发规范、推送边界 |
| `task` | 跨会话仍有价值的任务结论 | 某票的裁决与理由 |
| `shared` | 团队共享事实 | 角色分工、命名约定 |
| `coordinator-private` | 历史兼容读：康娜旧调度经验 | 不再新写；新条目写入项目｜冒险团记忆（物理仍 `project:<region-id>`） |

- 其他临时执行角色不建 role memory；记忆写入由 archivist 统一负责。
- 按新团长的记忆口径，取消独立角色记忆与团长个人记忆的新写入；`coordinator-private` 仅供历史读取，不新增。
- 白名单外的一律不写：模型自述、单次对话细节、无证据推断、别人的私密材料。

## 写入纪律（机械执行，不靠自觉）

1. **append-only**：日志只追加，不改旧行；纠正错误＝再追加一条反向记录。
2. **无证据不写**：每条至少一个可核验的 `evidence_refs`（文件:行号、URL、命令输出）。
   「我确认过」「已确认」「无」这类自述不算证据，工具会拒。
3. **可回滚**：每条可被 `rollback` 追加反向记录撤销；原记录永久保留，回滚本身留痕。
4. **冲突并列保留**：两条互相矛盾的记忆不静默择一，标 `conflicts_with` 交用户裁定。
5. **身份内核变更交团长**：涉及身份、职责、权限、核心底线的变化，先报告等批准，
   批准后按版本追加；本技能不自行改。

## 候选怎么整理

1. 收：从任务归档、证据文件、用户明确说过的话里挑候选，记清「原本是什么、经历了什么、现在如何」。
2. 判长期价值：一次性的留任务归档，不进长期记忆。
3. 查重：同一事实只留一条，旧的标「被取代」并指向新的。
4. 查冲突：与既有记忆矛盾时并列保留，标冲突关系与处置建议。
5. 补来源：每条候选至少一个证据指针；补不出就丢弃，不硬写。
6. 分类：任务事实 / 偏好 / 技能 / 关系 / 失败教训，写清适用范围与置信状态。
7. 批量写入后跑一次 `check`，确认全绿再回报。

## 不编造角色经历

- 只写有证据的**事实与约定**，不给任何角色编造「经历过什么」「当时怎么想」。
- 转述别人的话要能追到原始消息或来源；追不到就写「来源不明」或不写。
- 复盘用于改进流程，不用于无证据地评价人格。

## 命令

```bash
# 追加一条（写者只能是 archivist）
python scripts/role-memory.py append --log <日志.jsonl> --writer archivist \
  --scope task_fact --statement "…" --evidence "path/to/evidence:行号"

# 回滚一条（追加反向记录，原记录保留）
python scripts/role-memory.py rollback --log <日志.jsonl> --writer archivist \
  --target m-0001 --reason "…"

# 校验 / 看活跃条目
python scripts/role-memory.py check --log <日志.jsonl> [--json]
python scripts/role-memory.py show  --log <日志.jsonl> [--json]
```

兼容：旧日志里 `writer=coordinator` 的记录仍可读、可被 `check` 接受（历史不追溯改写）；
新记录一律 `writer=archivist`。

## 自检（回报前跑一遍）

- `check` 退出码 0，且 `ok: true`；
- 每条新记录都有非自述的 `evidence_refs`；
- 没有白名单外的域、没有 role memory、没有身份内核改动混进来；
- 冲突条目都并列保留，处置写清了；
- 回报只给结论＋候选条数＋需要用户裁定的项，不贴整库。

## 边界

- 不合并、不推送、不关票；发货仍是主会话的事。
- 不改 `roles/canon`、`roles/skins`、`registry.json` 等正本；要改先报告。
- 记忆写入归 archivist；账本自检用 `check`，发现问题按追加反向记录修正。
- 不替圣骑士判任务交付：本技能只管记忆账本，任务验收判词归 reviewer。
