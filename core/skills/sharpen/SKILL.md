# sharpen —— 开工前先锐化

> 一次只回答：这活真正要什么。产出一张 5 行卡，然后交回 `../gold/SKILL.md` §2 路由。

## 何时用

- 需求刚来、还模糊，派活之前先钉目标与验收。
- 用户给的是一句效果诉求，但没说是手段还是效果。
- 康娜自己判断「走哪条」之前的最后一道自检。

## 步骤

1. **专家视角**：三类信息各取一点——
   - 原始来源：这需求从哪来、原话是什么（用户原话优先，转述次之）。
   - 真实方法：这类问题业内实际怎么解（一句话，不展开教程）。
   - 一个外部核验点：改完后用什么外部可见的信号证明成了。
2. **目标一句话**：问自己「要的是效果，还是要的是手段」。
   - 用户说的是手段（用 X 做、改成 Y）⇒ 目标往上抬一层，写效果。
   - 效果不可判 ⇒ 标 unknown，按 `../principles/SKILL.md` §1 一次一问，问用户。
3. **规格体检**：
   - **放开**不服务目标的约束（形式、技术选型、历史包袱）。
   - **补上**可验收的约束（数字、边界、回归面）。
   - **留空**属于用户的选择（观感、优先级、取舍），不替用户填。
4. **出卡**：5 行，逐行写死（见下）。
5. **路由**：按 `../gold/SKILL.md` §2「判断走哪条」定去向；简单修也派 1 个可写 worker，康娜只验收。

## 输出（5 行，固定顺序）

```text
目标一句话：
真正的验收：
放开的约束：
补上的约束：
外部核验点：
```

- 每行一句；放开的/补上的可为多条，用顿号连写。
- 目标一句话与验收必须机检或人可复核；写不出验收 ⇒ 该行写 unknown + 要问的那一问。

## 用词与证据

- 只用四类词：`fact` / `inference` / `unknown` / `recommendation`。
- 卡里的约束来自用户原话就标 fact（引原话）；自己补的标 inference。
- 需要用户拍板的写 unknown，并列出那一问。

## 边界

- **只读**：不写代码、不改文件、不开票、不派活、不写记忆。
- 一次一问：要问用户时按 `../principles/SKILL.md` §1，每题给 2–3 个选项、推荐项第一。
- 不复制 `staff` 的拷问流程；需求大到要规划时，出完卡交 `../staff/SKILL.md`。
- 不改 `../gold/SKILL.md` 的任何判据，只按它的表路由。

## 自检

```text
5 行齐全，每行一句话
目标不是手段；验收可复核
属于用户的取舍留空并列了那一问
没有任何写动作
```
