# 并发与槽位

## 数量

| 维度 | 默认 | 上限 | 开关 | 计数口径 |
|---|---|---|---|---|
| run（一次开工） | 1 | 3 | `--ships N` | 按 run 集合独立计 |
| 子代理（并发） | 5 | 5 | `--crew N` | 按 run 集合独立计 |

- `--ships N` 一次创建 N 个 run，各自 worktree ＋ 分支，共享 `fleet_id`（`<宿主>-<时间戳><后缀>`）。
- 混搭曲速与跃迁时，给多条命令传同一个 `--fleet <ID>`，总数仍受上限约束。
- 不同康娜／不同 agent 框架互不抢占槽位；但 **touchset 冲突检测是全局的**。
- 用户说「曲速 2 船」「晚上用 3 船」→ 翻译成 `--ships N`，不问第二遍。

## 排队

并发满时新 run 进 `queued`；槽位空出后自动提升（`promote_queued`）。
`--tasks` 可在开 run 时直接写任务图，不必等 run 起来再 plan。

## 重试预算

- 子代理重派：同一任务 1 次。
- `return` 上限：3 轮。
- 失败重试：2 次。
- merge 冲突：自动 rebase 1 次。

预算是硬上限，不是目标。第三次尝试之前先换方法（`diagnosing-bugs`）。

## 目标分支与自动关票

- push 目标默认 `dev`；仓里没有 `dev`（例如已经并入 `main`）则用当前分支。
- 任务文本里的 `#123` 或 GitHub issue URL 会在发货时自动关票；识别不到就跳过，不阻塞发货。

## 吞并外部成果

`fleet assimilate <branch> --approve` 把别的分支成果并进来。
**必须用户先同意**：这条命令会改写当前 run 的 baseline，属于不可逆面。
