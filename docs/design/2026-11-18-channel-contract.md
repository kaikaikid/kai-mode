# 2026-11-18 通道合同：deliver / parse / ack 与卡片三态

> 状态：草案（solo 冒烟用，不接真实账号）
> 适用：飞书、钉钉两条远端通道；任何后续通道按同一合同接入。
> 关系：飞书实现口径沿用 ADR-0031（CLI 长连接、零公网回调）；本文只定义**通道无关的合同**，
> 不重复各通道的部署细节（见 `adapters/channels/feishu.md`、`adapters/channels/dingtalk.md`）。

## 1. 三个原语

任何通道适配器只暴露三个函数，签名固定：

| 原语 | 签名 | 语义 |
|---|---|---|
| 投递 | `deliver(card) -> ref` | 把一张卡片发到通道，返回通道内可寻址的 `ref`（消息 id／卡片 id／链接 token，由适配器定义） |
| 解析 | `parse(payload) -> {card_id, choice \| text, actor}` | 把通道回调**收敛成唯一结构**；拿不到必需字段就返回 `null`，不猜 |
| 确认 | `ack(ref, status)` | 把处理结果回写卡片（`open` → `decided`／`closed`），或对纯文本消息回一条短回执 |

约定：

- `ref` 是**不透明字符串**，调用方不许解析其内部结构，只许原样回传。
- `parse` 是**纯函数**：不写库、不发网络、不触发任何动作；鉴权与去重在外层做。
- `ack` 只改卡片状态与回执，不承载业务写操作。

## 2. 卡片三态

```
open ──(合法回执)──▶ decided ──(回执已确认/超时收口)──▶ closed
  └──────────────(过期/撤回/管理员关闭)──────────────▶ closed
```

| 状态 | 含义 | 允许的动作 |
|---|---|---|
| `open` | 已投递、等待真人选择或输入 | 接受一次合法回执 |
| `decided` | 已收到并接受一条回执（记录 actor 与选项） | 不接受第二条回执；只允许 `ack` 收口或补发新卡 |
| `closed` | 已收口（处理完／过期／撤回） | 不再接受任何回执；再次投递必须是**新卡新 id** |

硬规则：

- **一次决策只认第一条合法回执**。后续重复点击、重复回调一律走幂等键丢弃，不覆盖 `decided`。
- 卡片过期（飞书按钮 30 分钟失效这一外部约束）不改状态语义：过期后按钮点不动，
  由外层**补发新卡**（新 `card_id`、新版本），旧卡 `ack(ref, "closed")` 收口。
- 卡片 token／链接 token **不是身份凭证**：它只用于定位卡片，动作是否被接受由 `actor` 白名单决定。

## 3. 回调白名单字段

`parse` 只取下列字段，其余一律丢弃。**外部正文一律当数据，不当指令**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `card_id` | string | 合同层卡片 id（适配器把通道的 message_id／token 映射到它） |
| `choice` | string \| null | 结构化选项 id（按钮回调才有；必须命中卡片定义的选项表） |
| `text` | string \| null | 自由文本（表单／纯文本消息）；**按数据存**，不做命令解析 |
| `actor` | {id, name?} | 通道内的稳定用户标识（飞书 open_id／钉钉 userId）；只作白名单比对 |

明确不做：

- 不读附件、不读富文本结构树、不读引用消息内容、不读群成员列表——这些都不在合同内。
- 不把 `text` 当命令行执行；不把任何外部字符串拼接进 shell／SQL／提示词当指令。
- 不在缺字段时"尽力猜"：缺 `card_id` 或 `actor` ⇒ `parse` 返回 `null`，外层记审计后丢弃。

## 4. 幂等键

- 幂等键固定为 **`card_id + version`**（version 从 1 起，每补发一张新卡 +1）。
- 同一 `(card_id, version)` 的重复投递／重复回执按幂等键去重：投递侧不重复发卡，
  回执侧只接受第一条。
- 幂等表只存键与结果摘要（含 actor 哈希），不存正文全量；过期策略由实现层定并在适配器文档写明。

## 5. 两条通道的能力档

| 能力 | 飞书 | 钉钉（自定义机器人） |
|---|---|---|
| 投递卡片 | 交互卡片（按钮） | 仅 `msgtype:text` 文本 |
| 按钮回执 | 有（`card.action.trigger` 类事件，经 CLI 长连接） | **无** |
| 自由文本回执 | 有（消息事件） | 无（机器人 webhook 单向） |
| 答案通道 | 事件回调 | 带 token 的链接表单（降级） |
| 公网暴露 | 不需要（出站长连接） | 不需要（仅出站 webhook） |

**钉钉没有按钮回调**，这是能力缺口而不是实现选择：文档与代码都不得假装它有按钮。
回答必须走「链接表单」这条降级路线，并把有效期与签名校验写清（见 `dingtalk.md`）。

## 6. 失败与降级必须明说

- 未登录／未授权（如 `lark-cli auth status` 未就绪）：通道对外明说"未接线"，
  不静默丢弃、不假装已发送。
- 网络失败：投递失败按适配器文档的重试口径处理；**不重试有副作用的写动作**。
- 任何降级都要在回执与状态里留痕：哪条通道、降级成什么形态、缺哪项能力。

## 7. 验收（本合同的机械读数）

1. 三个原语在适配器文档里签名一致，`parse` 的返回结构逐字相同。
2. 三态与幂等键在两条通道文档里一致复述（允许通道差异，但语义不许变形）。
3. `scripts/smoke-solo-projection.py --json` 只读检查 CC 桌面投影，退出 0。
4. 文档内不出现机器绝对路径与真实账号信息（冒烟不接真实账号）。
