# 0002 单句入口、拷问定稿一次拍板与双轨换轨

## Status

accepted —— 2026-10-19 于项目仓起草并拍板（用户令「今晚全开」）。2026-10-23 判据正本迁入本仓；执行层部分已被 0003 重做（见下）。

## 出处与迁移

本文 D1–D3、D7 与各硬线为现行判据；与 0003 冲突处以 0003 为准。

## Context

用户是单一操作者，日常只用口令操作；诉求＝说一句话 → AI 判断 → AI 拷问 → 定稿 → 自动开跑。她能决策的层级＝大方向（ADR 级），细节交 AI 按头部企业规范自决。改造前入口层与执行层都是手工点火：开机喊口令、双轨人派活、出货靠 push 顺带。

实测病征六类：同一张票两个机长各做一遍（双实现）；产出堆在门口（十余笔未推、成果卡通道）；运行态账本写满贴死上限；门对什么都报红成长期红门（教人跳门）；人判队列积压（待拍与待验收成堆）；死锁堆积（stale 锁挂多日、票龄以周计）。

行业证据同向：合并队列（Bors/Zuul/GitHub merge queue）＝出货口是固定吞吐，上游加人只会堆货，药方是串行化＋批量化＋优先级，不是加 builder；瓶颈理论＝省在非瓶颈处的一小时是幻觉；看板＝Stop starting, start finishing；审查是瓶颈时不要让每对开发者+AI 只因车道有空位就继续产出；多智能体最常部署 generator-verifier ＋ 原子领取（重复领取 409）；人判不成为瓶颈＝响应 SLA 一个工作日、低风险改动事后抽查。

## Decision

### D1 入口＝`/kai-mode`，中立层实现（不挂任何编辑器）

规则写在仓库里（入口技能＋根说明指针；项目仓落点在项目仓配置面，由 set-kai-mode 初始化写入），任何 agent 一进仓库即生效；自动化挂在 git 钩子与系统计划任务上（0003 已把装配面推广为宿主中立，不写死某一种系统计划任务）。编辑器专属外壳（如某编辑器的斜杠命令）只做可选别名，不做命脉。理由：用户跨多个编辑器用 agent，把命脉挂到单一编辑器＝换工具即失效。

### D2 拷问＝一轮打包，只问大方向

- ≤5 问 / ≤2 轮，每题带推荐默认值；用户回「全按你说的」即整轮收。这是对家规「一次一问」的**窄例外**：拷问首屏允许成批，日常打扰仍一次一问。
- 只问 ADR 级（影响大方向）的分叉；细节不问，AI 按头部企业规范取默认并写入**代决清单**。
- 手法借鉴既有「全权授予＋一句路由＋翻人话」先例。

### D3 定稿＝清账 → ADR → 票 → 规划表，一条龙

定稿前先过票架：上游决策已被推翻／重复票 → 关；不该在本里程碑 → 转走；「超 30 天没动」**只列清单交用户，不自动关**（那是不可审计的永久范围丢失）。产物＝ADR＋票＋规划表；用户**只在规划表上拍一次板**。

### D4 双轨重切＝机长造 / 副机长出

- 机长：领票 → 开工 → 建 → 交活；副机长：审查 → 推 → 关票 → 清账 → 催验收；触发＝git 钩子＋定时督工。
- 改动 A（评审指定的「最小改动最大收益」）：出货**同步化**——每次交割立刻跑出货预检 → push → 关票，白天也跑、串行，不等夜里另起一条。
- 【0003 重做】造/出双轨已被四角色取代：机长／副机长同为管理角色不 push，施工／审查分离保留为子代理分工，出货集中到塔台独占（0003 D1/D5）；「出货不积压」判据由 60 分钟轮巡承继。

### D5 督工＝系统计划任务，夜间窗口每 15 分钟醒

（原文：Windows 计划任务 23:00–9:00、每 15 分钟；装配参考同机同仓已有的定时任务先例。）硬线：

- **单飞锁**：同一时刻只允许一个自动会话；已有会话在跑则本 tick 直接退出。
- **绝不进主树**：自动会话一律在独立 worktree 干活。
- **9:00 不硬切**：不再主动起新会话，正在跑的让它跑完——硬切留下脏文件 → 锁永不 stale，复现死锁病。
- **一律不删任何文件**：删除只在用户在场时执行。
- **显式关闭「错过补跑」**，以免白天撞进人工会话。
- 督工补漏四件事：扫货架、清死锁清单、对账、催验收；早报三段：干了啥、卡在哪、要她拍什么。
- 【0003 重做】15 分钟夜间督工已被塔台 60 分钟轮巡取代（0003 D1/D5）；单飞、隔离、不硬切、不删文件的可靠性判据并入 0003 的物理隔离与红线体系。

### D6 四处漏的修法

| 漏 | 决策 |
|---|---|
| 分派/归属 | 机长／副机长用独立 git 身份＋独立 worktree；认领 **fail-closed**（撞车即停，不「警告放行」）。【0003 重做】租约认领退役，归属改由「塔台写日表即领取＋写者各 worktree＋单写手」保证（0003 D2/D3） |
| 通行（push） | 出货同步化（D4 改动 A）＋通道故障明确停机报警，不静默。【0003】塔台独占 push；推失败按回执点名重试、不绕钩子（0003 D5） |
| 账本容量 | 运行态账本**写满即归档**（尾部转存到票面/日志），**不扩容**。【0003】运行态账本退役；有界判据由日表 5–10 行、施工回执 ≤40 行承继 |
| 红门 | 存量红**降级为只报不拦＋跟基线比**，不追全绿（追全绿＝逼人绕钩子） |

### D7 审批红线表

- **仍先问**：花钱；对外真发布（公开仓库/发版/发布包/交给第三方；**不含 push 自有远端**）；不可回滚（force-push、改写已推历史、绕钩子）。
- **放行**：库内开发期测试数据；删**已入库**的仓库文件（git 历史可捞回）。
- **新增安全锁**：删任何未提交（未入档）的内容——即别人工作区里的活——仍是先问。
- 【0003 承继】红线集原样进入四角色体系：踩红线只停那一张票并等人（0003 D6）。

## Consequences

- 正面：用户从「喊口令＋派活＋催验收」降到一句话＋拍一次板；出货不等夜里，积压当晚不再累积；角色硬分割＋fail-closed 认领机制性拦住双实现；督工有单飞/不碰主树/不删文件三道栏，不与人工会话抢锁。
- 负面：夜间自动开跑＝自动花钱，用户已明确接受；新增一个常驻计划任务与脚本，运维面 +1。
- 风险与缓解：无头会话「退出码 0」假绿 → 督工首跑自检一次最小运行，失败写告警文件并在早报点红；tick 与长任务重叠 → 单飞锁＋会话自报心跳；窗口边界残留脏文件 → 让会话跑完＋督工扫「可回收槽位」清单交人，不自动删锁；共用分支并发合并 → 同步化＋独立 worktree＋fail-closed＋合并串行；一晚治理资产膨胀 → ≤5 问＋定稿一条龙合并到同一批产物；自动关票误伤待验收票 → 自动关只限证据确凿三类，待验收/hold 一律不碰。
