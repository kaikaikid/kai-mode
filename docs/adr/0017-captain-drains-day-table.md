# 0017 机长滚动消费日表：待发货不占帽，发货批次归塔台

## Status

accepted —— 2026-10-26 用户令（#6）：「机长能够一直推进自己排班表上所有任务，塔台按情况分批提交就行」。

## Context

- [0003](0003-airport-rebuild-four-roles.md) 把「同时在飞 2 张」同时当成了**并发上限**和**批次**：`loops/loop-protocol.md` §一 写「名额上限把在飞票切成一批＝2 票；一批收尾是唯一安全的换手点」，塔台据此在日表写「本批收尾，建议换手」⇒ 机长跑两张就有一个正当的停。
- 已 `pass` 写进待发货的票仍占在飞名额，而发货（合并／push／关票）是塔台独占且每 60 分钟才醒一轮 ⇒ 机长必须空等收货，一夜的墙钟大头落在这段等待上（2026-10-26 现状复核）。
- 供给侧已经不是堵点：0.24.11／0.24.12 之后日表按「任务菜单＝区间上限排」，`tower` §8.5 已明写「在飞名额约束的是并发领工，不是表的行数」。本 ADR 只动消费侧的「批」语义。

## Decision

### D1 帽只算未完工票

审查 `verdict=pass` 且按判词格式写进「待发货」＝这票在机长侧**完工**，当场释放在飞名额。合并、push、关票由塔台独占（§十），机长不追发货、不等待、不替塔台占位。

### D2 帽是并发上限，不是批次

同时在飞不超过协议正本 §一 的名额；一张完工即从日表补下一张，**滚动消费到日表跑空**。跑空的可判定义＝收工门禁 `decision=STOP`，或 `REVIEW` 判完确实没活（`--ack-review`）。

### D3 停点只有五类

红线（[AGENTS.md](../../AGENTS.md)）／同错误签名连续两次早停／修 1 次仍 `fail`／`BLOCKED` 与恢复三方对不上／日表跑空。**「批收尾」「等塔台收货」不再是停的理由。**

### D4 换手点下沉到单票

安全换手点＝任一票的收尾自检三件齐（票面有判词、分支 HEAD sha 已记票面、该票工作树无未提交），不再是「一批两张都落判词」。塔台只在**发现机长停摆**时写「建议换手」，不因批收尾写。

### D5 发货批次归塔台自决

塔台按「待发货队列 ＋ 触面 ＋ 收尾门成本」自行分批，不与机长节奏对齐，不要求「本轮只收某批」；门红拆批定位、零删除合并路径、退回机长等既有判据不变。机长侧不因为「塔台可能这轮不收」而少开工。

### D6 数值不动

并发帽数值、同域不并列在飞、写串行、日表行数区间都保持原值——本 ADR 改的是「批」语义不是「帽」大小。要扩帽需要实测（宿主并发与 token），另立。

## 与既有判据的关系

- **0003 D6**：机长「各管 2 张 issue」按本 ADR 收窄解释＝并发上限；批语义与「批收尾＝唯一换手点」作废，0003 加演变注。
- **loop-protocol §一／§二／§七／§十**：条文按本 ADR 改写，§一 是名额数值的唯一家。
- **`tower` §8.9**：换手点判据从「本批全部落判词」改为「机长停摆」。
- **唤醒围栏不动**（[0010](0010-role-wake-fence.md)）：机长仍不唤醒塔台；待发货堆积由塔台每轮自查队列承担，不由机长点火。

## Consequences

- 一夜推进量的上限从「2 张 × 醒着的轮」变成「日表行数」，机长的停只剩五类真有理由的停。
- 塔台一轮可能面对更多待发货票，收尾门与合并成本上升——由 D5 的自决分批与门红拆批承担。
- 机长不追发货 ⇒ 判词 `pass` 长期没发的票要靠塔台日报与 Issue 状态暴露；机长不兜这个底，也不因此停。
- 风险：释放在飞帽后同域票可能提前开工——同域不并列在飞的铁律仍在 §一 兜，塔台排表与本 ADR 不冲突。
