# 0018 跃迁窗口内的自主裁决：取舍题改派裁决子代理，不向用户提问

## Status

accepted —— 2026-10-26 用户令（#6）：「我需要跃迁模式下能够自主的决策完成任务，有什么决策的开一个高智商的子代理来思考判决，不要老是提问」。同向旧令：2026-10-21「跃迁期间子代理做决策不行吗？实在需要决策应该延后或者铺任务的时候就问」。

> 本 ADR 说的「跃迁」＝用户的**自治窗口**口令，与 0003 清退的旧机制「8 条跃迁」无关；旧机制不复活。

## Context

- `loops/loop-protocol.md` §十一 把「产品向没定论」判给「写卡点评论，交塔台／地勤攒批问用户」；在夜里跑到清空的窗口里，这条把最长一段墙钟交给了一个睡着的人。
- 实测信号一致：1021 她拒收「等」但接受「延后」；1023 追加「只能 handoff 留言、禁止呼唤其他角色」⇒ 中途问人是当时唯一还能停的口子，也是她最不满的口子。
- 卡点不在权限层：宿主可能根本没有 per-agent 硬权限（`adapters/README.md` §2／§3 三级降级，最软一档只有提示词）；把「别问」做成权限开关治不了提问。
- 需要新判据而不是一句「自己决定」：谁来判、判成什么形状、判错了怎么撤、哪些题仍然不许判。

## Decision

### D1 跃迁窗口怎么开、怎么算在窗内

用户对某条机长／副机长会话说出「跃迁」，或明示「连续跑到清空／别打扰我自己做」⇒ 该会话进入跃迁窗口；会话结束、用户撤回或换人接手即出窗。窗口状态**不落配置键**（口令即判据，避免造一个没有读者的字段）。

> **superseded_by 0019 D5（2026-10-26）**：本 D1 的「会话绑定开窗」已作废——绑在会话上＝继任班／定时器班一律出窗，
> 又回到「为取舍问人或写卡点停票」（0019 E5）。现行口径：**取舍题派裁决子代理是默认路径，开窗才用是错的**；
> 「跃迁」口令只保留「连续跑到日表清空、不逐票请示」这一条语义（该语义 0017 已立法）。
> 本 ADR 其余各条（D2 除开窗前提外的裁决机制、D3 形状、D5 两类不裁、D6 幂等与预算）**仍然有效**，原文不删。

### D2 取舍题改派裁决子代理

窗内遇到「没定论的取舍」（技术取向之外的方案选择、口径归并、优先级、边界宽严）⇒ 派第七人格 `adjudicator`（新上下文、只读、模型读项目实例 `models.agents.adjudicator.model`）出裁决，机长按裁决执行并在票面留痕。**窗内不为取舍向用户提问。** 技术怎么实现仍按 §十一 自决，不需要裁决子代理。

### D3 裁决形状

首行 `ruling=`，四件：争点（两种过法各一句）／判据（指针或实测读数，不写感觉）／所选与理由／撤销路径与改判条件。正本住 `agents/adjudicator.md`「输出契约」，协议与技能只留 marker 名与指针。`ruling=defer`（延后那一刀、继续别的活）是合法答案，**不许把 defer 包装成提问**。

### D4 红线不进窗口

花钱／对外真发布／不可逆／删未提交内容 ⇒ 仍只停该票并等人（[AGENTS.md](../../AGENTS.md) 红线正本）。裁决子代理无写权限、无权裁红线；机长也不得靠裁决或改授权规则给自己放行。

### D5 两类题连裁决子代理也不裁，按上报不按下问

① 两份都已生效的正本互相否掉（判词时间线与全貌在岗位侧，子代理只吃一张窄派工卡）；② 需要人眼判观感（「好不好看」不机器判）。处置＝延后该刀＋写进 Issue 评论或日报，窗内继续跑别的活。

### D6 幂等与预算

同票同争点不重派（票面已有 `ruling=` 就引用它）；两次裁决互相否定 ⇒ 停止再派，转 D5。裁决不吃 §七 的失败与早停额度（它不是重试施工）；一票默认一次裁决，多于一次要在票面写清为什么。

### D7 播报义务不变

§八 的「同票阻塞累计超 10 分钟播报一次」照旧——播报是状态报告不是提问。跃迁免的是逐票请示，不免播报、不免留痕。

### D8 宿主中立

裁决子代理是「新上下文只读子代理」这一人格，条文不写宿主工具名。宿主开不出独立上下文 ⇒ 机长自己在同一上下文里判并按 D3 留痕，缺件按 `adapters/README.md` §6 登记 `no-subagent-slot`，不静默跳过。

## 与既有判据的关系

- **§十一 决策分流**：四档变五档——「产品向没定论」在窗内改走 D2，窗外出卡点问用户；红线档与「有定论直接做」不动。
- **0003 D6／§七**：失败与卡点口径不变；裁决不是第二次失败。
- **0010 唤醒围栏**：不动。裁决子代理是**票内委派单元**（D5 of 0010 明写子代理不受围栏约束），不是角色会话。
- **0014／0015**：新人格只带一个键 `models.agents.adjudicator.model`，消费者＝装机 agent 与 `dispatch.md` §6，符合「键必须有活消费者」；不发明模型 slug。
- **`agents/README.md` §4**：「模式先于人格」仍然成立——本条是「性格、权限与模型档都不同」的新增档（要出的是有约束力的选择，不是 pass／fail），故开第七人格并在此登记理由。
- **0007 D4／0008 D1 的「六人格」**：那是当时的名单读数，不是上限；第七人格的登记理由在本 ADR，
  模板 `models.agents` 键集与 `agents/*.md` 由 doctor `agents-contract`＋`config-instance` 双向对账（漏一格即红）。

## Consequences

- 一夜的提问次数从「每道取舍一次」降到「红线 ＋ 人眼项」；代价是错判由机长执行、错放风险上升——由 D3 的撤销路径与改判条件在票面留痕兜底。
- 决策留痕从「用户拍板」变成「子代理判词＋可撤销」，事后追责面要读 `ruling=` 评论；这符合「可见面与红线归人」（原则技能 `visible-and-redline-only`）。
- 新增人格带来装机面：`agents/README.md` §4 表、模板模型槽、`dispatch.md` §3 谁能派它——三处同批改，漏一处就红（`agents-contract` 与 `config-instance` 双向对账）。
- 提问不会归零：红线与人眼项仍问，且这是刻意的（不自批）。

## 验证

- `python scripts/doctor.py --with-tests` 全绿；`agents-contract` 认到第七人格，且计数守卫不再放过写死的个数；
  同仓并行 lane 的在制件若带红，按归属另记，不由本票兜，也不许为它放宽判据。
- 手工：窗内出现取舍题 ⇒ 票面出现一条 `ruling=` 且没有向用户的提问；红线仍写「停该票等人」。
- 手工：窗内出现「两份正本互斥」⇒ 只看到延后＋上报，看不到第三个裁决。
