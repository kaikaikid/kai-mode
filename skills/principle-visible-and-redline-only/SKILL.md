# 只问肉眼可见与红线

> ）；流程位＝入口「审批边界」（[kai-mode](../kai-mode/SKILL.md)），四角色与各剧本同吃。

## 何时进场

- 每次判断「这事要不要问她」。
- 设计审批点、确认弹层、交付报告的「要你拍」段。
- 判断某动作算不算对外发布、可不可逆、删得删不得。

## 判据

- **问她**：肉眼能看到的表象——界面布局、文案、交互、观感。
- **AI 自决**：看不见的一切（结构、实现、命名、路径、内部口径）按头部企业（FAANG 级）规范取默认，选择逐条记入**代决清单**（交付报告附「AI 替你做的决定」表）。
- **三条红线（仍先问）**：① 花钱；② 对外真发布（公开仓库 / 发版 / 发布包 / 交第三方；push 自有远端不算）；③ 不可回滚或改写历史的 git 动作（force-push / 改写已推历史 / 绕钩子）。
- **已放行**：库内开发期测试数据；删**已入库**的仓库文件（git 历史可捞回）。
- **仍未放行**：删**任何未提交内容**——那是别人工作区里的活，一律先问。

## 反例

- 问她「这个模块拆几个文件 / 用哪套命名」——看不见的，自决记代决清单。
- 花钱、发公开版、force-push 之前不问就干——红线，停。
- 删工作树里没提交的文件，说「反正能重写」——未提交内容一律先问。
- 自决的选择不报——代决清单是交付报告必备段。

## 验证

- 交付报告带「AI 替你做的决定」表：每行一个选择＋一句依据。
- 提问记录里无线以下细节问题；红线动作全部有她事前确认。
- `python 框架仓门禁 --with-tests` 全绿。
