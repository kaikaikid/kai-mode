# 缺件如实登记

> 判据出处：[0004 D1/D4](../../框架仓旧裁决)（读不到就 rc≠0 报缺件，永不猜）；流程位＝[set-kai-mode](../set-kai-mode/SKILL.md) 第 0/3/6 步。

## 何时进场

- 探测发现任何缺口：缺文件、缺定时口、缺解释器/node/依赖、缺项目配置实例、缺权限。
- 想报「已完成 / 已装好 / 已实现」之前——先对一遍有没有拿替代品顶数。
- 读数取不到、命令 rc≠0、校验三面有红。

## 判据

- **缺件写三格**：**缺什么**（口/文件/字段/权限）、**卡在哪一步**（哪条流程跑不下去）、**要谁拍**（她拍，还是等哪个口）。
- 三个不许：
  - **不许写成已实现**——「没定时口就人工拉起」是缺件登记，不是已实现；
  - **不许静默吞错**——红了报红，退出码 0 只代表真到手的程度；
  - **不许猜路径写下去**——读不出就 rc≠0 如实报，不编近似值。
- 登记落到**要拍的人看得见的地方**：项目配置 `paths.handoff_dir` 当日日报「要你拍」段或平台私有清单，附缺的是什么口、什么权限。
- 登记≠完事：补法走缺口清单流程，她点头才动手。

## 反例

- 宿主没有定时口，回复写「定时器已配置」——谎报，写三格。
- doctor 有红，总结说「基本完成」——静默吞错。
- 库位读不出，猜一个路径写进脚本——永不猜路径。
- 缺件只留在会话里没进日报——她看不见＝没登记。

## 验证

- 每条缺件记录三格齐全，且能在日报「要你拍」段找到。
- 反向抽查：凡报「已实现」的项都有现测证据（回读 enabled、rc=0、哈希一致）。
- `python 框架仓门禁 --with-tests` 全绿。
