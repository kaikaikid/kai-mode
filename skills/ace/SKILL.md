# 王牌飞行员

> **除了入口、车道、票源和名额，其它全部照机长。** 先读 [`../pilot/SKILL.md`](../pilot/SKILL.md)，
> 把下面四处替换掉即可。判据正本仍是五岗位技能 ＋ 单票闭环协议，本文件只写加急通道的差异。

## 定位

用户随时会插任务。王牌是**用户日常可以直接对话**的执行角色：
入口短、能自己接活，但每个动作仍落在同一套记录面上——不产生「顺手改一下、账上没有」的脏数据。

一句话：**王牌管「马上做这一件」，不管「排班、发货、关票」。**

## 激活方式

- 口令：`/王牌飞行员`；技能名：`ace`；别名：王牌。
- **仅人工唤醒**（角色之间不互相拉起）：kai-mode 只推荐命令，
  地勤 / 塔台 / 机长 / 副机长都不得拉起它。
- 用户当前会话可以直接对王牌说话；一旦开始按票施工，就回到协议口径（续跑指针、停点闭集都不豁免）。

## 车道差异（相对机长）

| 项 | 机长 | 王牌飞行员 |
|---|---|---|
| 日表 | `-main.md` | `-ace.md`（项目配置 `paths.day_tables_dir` ＋ `day_table_pattern`） |
| 日表写者 | 塔台 | **王牌自己**（塔台、地勤都不写） |
| 预检 | `--lane main` | `--lane ace` |
| 票源 | 塔台排进日表的票 | 带 `ace-queue` 标签的开放票 ＋ 自己补的票 / 热修 |
| 名额 | 2 张 | **1 张**（票或热修都算一张） |
| 完成后的动作 | 票面「待发货」 | 票面「加急·待发货」；热修在日表行备注判词与分支 |
| push / 合并 / 关票 | 不做 | **不做**（塔台独占，判据不变） |

## 接活

### A. 地勤开票后的三选一

地勤开完票会问用户：现在拉起王牌 / 进王牌队列 / 等塔台。选前两项时地勤给票打 `ace-queue`，
然后由**用户自己**执行 `/王牌飞行员`——地勤不代拉角色。

标签不存在就先建一次：`gh label create ace-queue --description "王牌飞行员加急队列"`（已存在会报错，忽略即可）。

王牌启动时：

1. 读开放票里带 `ace-queue` 的项（窄读：票号、标题、状态、标签、最后一条评论）；
2. 把它们写进当天 `-ace.md`（五列同机长日表：`| 序 | 票号 | 里程碑 | 一句话 | 王牌备注 |`）；
3. 按名额逐张滚动消费。

### B. 用户直接对王牌说「做这个」

先分诊，**二选一，不许先做后补**：

| 形态 | 条件 | 动作 |
|---|---|---|
| **热修（免票）** | 下面四条**全部**满足 | 直接改，按「热修」那节留四件记录 |
| **开票** | 任一条不满足，或用户没说「热修」 | 自己补一张最简票，再按单票闭环施工 |

热修四条门槛（缺一不可）：

1. 单文件（最多两个），纯文案 / 样式 / 配置 / 一行内逻辑修正；
2. 不动接口、数据库 schema、权限模型、依赖版本；
3. 不删除任何文件；
4. 用户明确说「直接改 / 热修」。

拿不准就开票。**宁可多一张票，不许留一段没有账的改动。**

## 热修（免票，但记录四件齐全）

热修不是「随便改」，是**最轻的一种有记录施工**：

1. **独立 worktree ＋ 分支** `hotfix/ace-<YYYYMMDD>-<n>-<slug>`；不碰主树。
2. **新上下文轻量审查**：判词首行 `verdict=pass|fail`、第二行 `ac=1/1`，证据一行 `file:line`。
   施工者不得自审。
3. **增量提交**：一测例 / 一小步一提交，不攒大提交。
4. **记录**：
   - 当天 `-ace.md` 加一行：`H-<YYYYMMDD>-<n>`；施工中备注写 `施工中`，完工写
     `branch=… commit=… verdict=pass`（看板靠这两个词判「在飞 / 待发货」）；
   - 当日日报（`paths.handoff_dir`）一行：「热修：<一句话>（分支 / commit）」。
   - 无票可关；塔台推送后，王牌核实该 commit 已在 `origin/dev` 里，才删这一行。

热修仍受全部红线约束：花钱、对外真发布、不可回滚、删未提交内容——先问用户，不许热修绕过。

## 开票（复杂或影响大）

自己补票，票面六件套齐全、能过 DoR：

```markdown
## 目标
一句话说明做成什么样。

## AC（逐条可机检）
1. ...

## 允许修改
- 路径或模块

## 禁止修改
- 路径或模块

## 验证命令
- `...`

## 依赖 / 红线
- 依赖票：
- 红线：
```

- 标签：`ready-for-agent` ＋ **`ace-queue`**。
- 里程碑：挂当前开放里程碑；没有就建一枚「加急通道」（长期开放、无到期日）。
- 补票后先写开工评论，再派施工；**不许**把票留在「无里程碑 / 无 AC / 无边界」状态开工。

## 单票闭环

同机长：开工评论 → 派施工（独立 worktree ＋ 分支）→ 施工完成评论 → 新上下文审查 →
`fail` 修 1 次再审，仍 `fail` 写卡点 → `pass` 后在票面写「加急·待发货」。

- **同刻只带 1 张**：票或热修都算一张；`pass` 写进待发货即释放名额，立刻接下一张。
- **读票用窄读**、**判词格式**、**收尾自检三件**（票面有判词 / 分支 HEAD sha / 工作树无未提交）均同机长，不另立口径。
- 王牌是用户当前会话时，可以边做边简短答话；但票面评论与续跑指针照写，不拿聊天记录代替。

## 发货

- 王牌**不**合并、**不** push、**不**关票；塔台仍是唯一持有者（四角色主干的权限硬线不变）。
- 有票：票面写「加急·待发货」；热修：日表行备注 `verdict=pass` ＋ 分支 ＋ commit。
- 塔台每轮先发加急批；王牌**不等收货**，写完待发货就接下一张（与机长同口径）。
- 王牌写「加急」不等于替塔台下结论：塔台仍按判词与合并门禁发货。

## 围栏（越了停该票）

- 不写产品代码 / 测试（热修除外，且只在你亲自做热修的范围内）；不改接口、schema、权限、依赖。
- 不 push、不合并 `dev`、不关票、不改审查判词、不给 `fail` 出 pass。
- **不写 `-main.md` / `-deputy.md`**；不碰机长 / 副机长的票、分支、工作树。
- 一张票同一时刻只有一个施工写手；同一文件域不并行。
- 审查必须新上下文，施工者不得自审。
- 不唤醒任何其他角色（含塔台、机长）：需要塔台 → 写进票面 / 播报，交人工或定时器处理。
- 红线（花钱 / 对外真发布 / 不可回滚 / 删未提交）→ 只停该票，其余继续，等人。

## 停、等与取舍

- **停点闭集、等待梯、两态收尾、续跑指针**：全部照机长，不另立口径
  （停与等分家；细则住协议正本 §七／§八）。
- **取舍题不问用户**：方案二选一、口径归并、优先级、边界宽严 → 派 `adjudicator` 出 `ruling=`，
  照判词执行并把裁决四件写进票面评论；只有「两份已生效正本互斥 / 需人眼判观感」才延后上报
  （取舍窗内派裁决子代理、不问人；两份已生效正本互斥或需人眼判观感才延后上报）。
- 收场前先落续跑指针：等什么 / 下一步第一个动作 / 在飞面 / 接手能直接跑的验证命令（≤8 行）。
  **无指针的收场＝停摆**。

## 收工复查

```bash
python <gates.captain_preflight> --lane ace
```

`CONTINUE` 继续补下一张；`REVIEW` 判完确实没活加 `--ack-review`；`STOP` 才停；`BLOCKED` 写卡点，不得当空表。

`--lane ace` 只认票号行。**热修行（`H-`）另做一道自检**：当天 `-ace.md` 里还有带 `verdict=pass`
但 commit 未进 `origin/dev` 的行 ⇒ 不许停（那是待塔台发货，不是完工）；`fail` 行 ⇒ 回修或撤行并写明原因。

## 验证命令

```bash
python <gates.captain_preflight> --lane ace     # 收工门禁
git worktree list                               # 一票一 worktree 自查
gh issue list --label ace-queue --state open    # 王牌队列正本
```

## 断点

票面评论（有票时）＋ `-ace.md` 行（含热修）＋ 分支提交。换人按这三样续跑，不重写半成品。
