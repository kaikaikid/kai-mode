# 可靠性：租约、重试、去重、恢复、熔断

> 目标不是“永不失败”，而是**失败可见、可停、可恢复、不重复**。
> 所有默认值都在项目配置 `limits` 里可覆盖；本文给的是出厂值。

## 一、默认限额

| 键 | 出厂值 | 含义 |
|---|---|---|
| `pilot_global_wip` | 1 | 试点期同时编码任务数 |
| `per_group` | 2 | 稳定期每组并行（文件域不重叠） |
| `global` | 4 | 稳定期全仓并行 |
| `max_attempts` | 3 | 单票最多尝试轮次 |
| `same_error_stop` | 2 | 同一错误签名出现几次即停 |
| `task_timeout_min` | 60 | 单票墙钟上限 |
| `attempt_timeout_min` | 30 | 单次尝试上限 |
| `run_timeout_min` | 120 | 单班/单次运行上限 |
| `token_ttl_min` | 45 | 跑道牌/出货牌心跳过期阈值 |
| `lease_ttl_min` | `null` | 文件域租约 TTL（未实现；先改 scope-check） |
| `cooldown_min` | 15 | 同目标重复按铃冷却 |
| `circuit_breaker_failures` | 3 | 连续启动失败/门红触发熔断 |
| `daily_wallclock_min` | 480 | 每日总运行时墙钟 |
| `daily_token_budget` | `null` | 可测量时才设；不可测不假装有 |

到任一项上限：写 `blocked` 或 `failed`，留读数，停手；不许“再试一次看看”。

## 二、租约

- **一票一租约**，逐枚文件/目录；`current-task-<票>.json` / `lease-<票>.json` 当前是 **first-wins 快照**，字段是 `allowed`/`baseline`/`active`，**没有 `expires_at`、没有 TTL**；收工必须 `scope-check clear`，否则下一班拿着上一班的职权硬干。
- **45 分钟 TTL 适用于跑道牌/出货牌**（`on-duty-*.json` 的 `heartbeat_at`），不是文件域租约；两者别混。
- 文件域租约的失效靠 `scope-check` 的槽位/车道 stale 判据与人工 clear；要加 TTL 必须先改 `scope-check.py` 并留迁移票（当前未实现）。
- 租约失效/释放 ≠ 工作丢失：树、提交、检查点仍在；新 owner 先对账再决定继续或重做。
- 租约不跨班留存；收工不销＝下一班拿着上一班的职权硬干。

## 三、重试与同错早停

- 只有 `validating → repairing` 允许自动重试；`failed` 不自动复活。
- 每次重试：**新上下文、新 attempt、同一合同**；不允许把坏会话续着聊。
- 错误签名 = `sha256(失败命令 + 失败测试 id + 关键错误行)`；连续两次相同 ⇒ 立即停，写 `failed`/`blocked`，不再消耗第三次。
- 第三次尝试前必须有一次“改变假设”的动作（换复现路径、加日志、缩小范围、查依赖），否则不许开跑。
- 高风险票的修复必须重新走审批，不因“只是修一下”自动降级。

## 四、去重与幂等

每个有副作用的动作先算 `event_id = sha256(action + ticket + attempt + target)`，在 `events.jsonl` 里查：

| 动作 | 幂等检查 |
|---|---|
| 开票 | 按标题/父票搜索，已存在则复用 |
| 开工树/分支 | 分支已存在则复用；先 `git worktree list` |
| 提交 | 同票同 diff 已有提交则复用 |
| 开 PR | 按 head 分支查已有 open PR；有则更新，不重复开 |
| push | 先 `git ls-remote` 比对远端 sha |
| 关票 | 已 closed 则只补证据，不重复关 |
| 发 handoff | 同 `seq`/同内容已存在则覆盖，不追加第二份 |
| 按铃 | 目标在岗（令牌/心跳/`runningAt`）⇒ 不按 |

**“命令 exit 0”不算完成**：推送要两路回读，关票要回读状态，PR 要回读编号与 head sha。

## 五、崩溃恢复

进程被强杀、宿主重启、会话超时后，按固定顺序恢复：

1. **读事件**：`events.jsonl` 最后一条该票事件；确认 `event_id` 链无断裂。
2. **读状态**：`task-state-<票>.json`；若 `updated_at` 落后于事件，以事件为准并重写状态。
3. **读 git**：分支、HEAD、commit、是否已并入 dev、工作树是否脏。
4. **读 GitHub**：票 open/closed、PR 状态、审批评论。
5. **判定**：
   - 工作已完成且证据齐 ⇒ 直接推进到下一合法状态；
   - 工作未完成且租约过期 ⇒ Tower 重发租约，新 owner 加 attempt；
   - 三方冲突/无法判定 ⇒ `blocked`（reason=`recovery-mismatch`），交人。
6. **不重复副作用**：恢复后先做 §四 的幂等检查，再决定是否重发 PR/评论/push。

恢复流程必须可复跑；恢复脚本本身不写业务代码，只对账与推进状态。

## 六、熔断与停机

触发任一条件 ⇒ Coordinator 写 `hold-<role>` 或 `hold-all`：

- 同一目标连续 `circuit_breaker_failures` 次启动失败；
- 同一票连续 3 次同因门红；
- 日墙钟/预算到阈值；
- 发现共享状态损坏（索引、令牌、主树）且无法自愈；
- 安全/权限拦截（不是可重试错误）。

停机牌**不自动过期**；只有用户能清（`resume` 只清牌，不替用户改方向）。Coordinator 不自行解牌。

## 七、并发与工作区

- 同一文件域同一时刻只允许一个执行者；租约是唯一凭据。
- 每个执行体一个工作树；不在主树直接改；不在车道里跑会改写共享 `node_modules` 的包管理器命令。
- 共享可变状态只有两个：**dev 分支**与**全局出货牌**。二者都由 Ground 单点操作。
- 默认不允许两个执行体在同一工作区并行；要并行必须文件域不重叠且各自有树。
- 代际上限 1：被叫起来的班不得再起会话/再建任务；需要续跑由 Coordinator 下一次按铃。

## 八、预算

- 每次尝试记录：开始/结束、墙钟、token（若宿主提供）、工具调用数、产物大小。
- 日预算到 80% ⇒ 通知用户但不一定停；到 100% ⇒ 停止开新票，只收尾。
- 无法测量 token 的宿主，明确写 `cost=unknown`，不许编造读数。
- 预算不是“必须花完”的配额；闲时零动作是正确的。
