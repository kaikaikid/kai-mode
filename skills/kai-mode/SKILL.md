# Kai Mode —— 所有剧本的统一入口

> 落地 0002 单句入口/拷问/定稿 与 0003 四角色机场。
> **中立层**：规则住仓库里，任何 agent / 任何编辑器一进仓库即生效；斜杠命令只是可选别名。

## 这是什么

`/kai-mode` 是**所有剧本的统一入口与顶层抽象**：用户说一句话，它判断、拷问、定稿、路由。
**它不执行具体活**——不写代码、不开票、不排班、不 push；那些归四角色和各剧本。

```
用户一句话
  → ① 判断（新想法 / 熟活 / 已有票）
  → ② 拷问 ≤5 问（只问大方向，每题带推荐默认）
  → ③ 定稿：清账 → ADR → 拆票草案 → 规划表
  → ④ 用户只在规划表上拍一次板   ◄── 全流程唯一必须她按的地方
  → ⑤ 路由：地勤开票 · 机长/副机长执行 · 塔台排班发货 · 其它剧本
```

## 入口约定

| 你说什么 | 走哪 | 说明 |
|---|---|---|
| 新想法 / 方向未定 / 一句话需求 | `/kai-mode` | 默认入口；判断、拷问、定稿、路由 |
| 已定方案要开工 | `/塔台` 排班，或熟活直喊 `/机长`、`/副机长` | 机长只做日表里的票；表空就请塔台补 |
| 排班 / 发货 / 关票 | `/塔台` | 也可等 60 分钟轮巡自动跑 |
| 聊规划、开票、记想法 | `/地勤` | 开票权归地勤 |
| 「loop」 | **不是口令** | 历史叫法；单票闭环是机长/副机长共用协议 |

四角色只是默认的机场剧本；**剧本不限于四角色**——新增剧本在项目配置实例 `registry.playbooks[]` 登记一行即可（框架仓旧裁决，项目仓 router.md 已退役），入口不必改。

## 四个角色（职责与正本）

| 角色 | 口令 | 管什么 | 正本 |
|---|---|---|---|
| 地勤 | `/地勤` | 跟用户对话、规划、开票、收 BOOM 想法 | [`skills/ground-crew/SKILL.md`](../ground-crew/SKILL.md) |
| 塔台 | `/塔台` | 独立岗位；默认每 60 分钟被唤醒，也可人工唤醒；kai-mode 只推荐命令；先发货、后补排班（排班放最后）；合并、push、关票 | [`skills/tower/SKILL.md`](../tower/SKILL.md) |
| 机长 | `/机长` | goal 模式读 `-main` 日表，同时最多 2 张 | [`skills/pilot/SKILL.md`](../pilot/SKILL.md) |
| 副机长 | `/副机长` | 同一条 loop 的另一分支，读 `-deputy` 日表 | [`skills/copilot/SKILL.md`](../copilot/SKILL.md) |

**权限硬线**：塔台独占 push 与关票；机长/副机长只管理不写码、不 push；地勤只开票不施工；kai-mode 只做入口。
细则以 0003 D1／D5 为准，本文不复述。

## 拷问规则 —— 流程位＋指针

- **流程位**：拷问＝流程第②步（见上），交互顺序与入口判断咬死，留在流程里。
- **判据细则唯一正本**：[`skills/principle-ask-one-question-at-a-time/`](../principle-ask-one-question-at-a-time/SKILL.md)（何时进场/判据/反例/验证）；本节不复述细则。

## 定稿规则 —— 清账 → ADR → 拆票草案 → 规划表

1. **清账**：上游决策已被推翻 / 重复票 → 关；不属于本里程碑 → 转走；超 30 天没动 → **只列清单交用户，不自动关**。
2. **ADR**：大方向决策落项目 ADR 目录，落点从项目配置实例 `registry.adrs.dir` 读（缺实例→按 框架仓旧裁决 报缺件）。
   方法用外部技能 `domain-modeling`（术语挑战、ADR 三条件、GLOSSARY 落点），本仓不 fork。
3. **拆票草案**：按里程碑拆成可执行工单草案（目标、AC、允许/禁止修改、验证命令）。
   方法用外部技能 `to-tickets`（垂直切片、阻塞边、宽重构 expand–contract），本仓不 fork；**只出草案，开票归地勤**。
4. **规划表**：汇总成一张表——她**只在规划表上拍一次板**；批准后路由**地勤开票**。

## 审批边界 —— 流程位＋指针

- **流程位**：拍板前每次「要问她吗」的判断，以及四角色、各剧本的审批点，都吃这一条。
- **判据细则唯一正本**：[`skills/principle-visible-and-redline-only/`](../principle-visible-and-redline-only/SKILL.md)（何时进场/判据/反例/验证）；本节不复述细则。

## 路由：拍板之后

| 需求形态 | 路由给 | 交付物 |
|---|---|---|
| 需要开票 / 改票面 | 地勤 | Issue（挂里程碑、`ready-for-agent`、AC 与禁区） |
| 有票要执行 | 机长 / 副机长 | 按日表开工；每票 1 施工 + 1 审查 |
| 要排班 / 发货 / 关票 | 塔台 | 日表、一次合并 push、关票回执 |
| 不属于四角色 | 对应剧本 | 登记行收进项目配置实例 `registry.playbooks[]` |
| 要全景 / 看进度 | **看板**（三层：数据 ＋ 展示 ＋ 触发） | 数据层 `handoff/60-board/` 卡片；展示层 [`flight-info`](../flight-info/SKILL.md)（口令 `/航班信息`）的 `board.json`（AI 读）与 `index.html`（人读） |

**kai-mode 只做路由与推荐**：打印/写出 `/塔台`、`/机长`、`/副机长`、`/地勤` 等命令，交人工执行；
**不调用会话创建口，不自动起角色**（框架仓旧裁决）。宿主缺能力时写进
`/set-kai-mode` 的缺件登记，不猜路径、不硬起。
**唤醒塔台的人名单（现阶段，框架仓旧裁决）**：人工口令、60 分钟唤醒定时器两路；
kai-mode 只推荐命令，不在唤醒名单；**机长/副机长也不得唤醒塔台**（后续可评审放开）——
它们需要塔台时写进交付/播报，由人工或定时器处理。

## 分层与硬互斥线

| 层 | 管什么 | 正本 |
|---|---|---|
| 入口层 | 判断、拷问、定稿、路由 | 本文件 |
| 方法层 | 怎么干（四岗位技能 ＋ 子代理人格 ＋ 单票闭环） | agents/ ＋ loops/ ＋ 各岗位技能 |
| 调度层 | 谁在飞、排班、并发、发货 | 0003 ＋ 塔台技能 ＋ 项目配置 `paths.day_tables_dir` 日表 |
| 记录层 | 票状态与证据 | GitHub Issue（唯一事实源）＋ 日表 |
| 展示层 | 人看的全景（不改状态） | 数据 `handoff/60-board/` ＋ 展示 [`flight-info`](../flight-info/SKILL.md) |

- 入口**不复述**任何一层的判据；剧本**不写**谁在飞 / 并发 / 发货；调度**不改**剧本判据。
- 一个语义只许一个家：判据见 [`principle-one-semantics-one-home`](../principle-one-semantics-one-home/SKILL.md)。

## 设计取舍

全权授予 · 一句路由 · **翻人话**；另加「拷问只问大方向 ＋ 定稿一条龙 ＋ 拍板只一次」。

- **正文不常驻**：治理正本「索引一行常驻 ＋ 叶子按需读」，派活前先问这一发要不要整读。
- **传指针不传全文**：给子代理文件路径与票号，不粘正文；回收只收回执上限内的结论（见 `loops/loop-protocol.md` §五）。
- **仪式随规模塌缩**：判据见 [`principle-ceremony-collapses-with-scale`](../principle-ceremony-collapses-with-scale/SKILL.md)。
- **默认往前走**：判据见 [`principle-measure-dont-ask`](../principle-measure-dont-ask/SKILL.md)。
- **不搬**并行舰队那套机器（与 0003 的单写手/隔离口径相反）。
