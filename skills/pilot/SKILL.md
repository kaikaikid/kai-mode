# 机长

> 判据正本：四岗位技能正文 ＋ 子代理口径「不设数量硬上限」。流程细节只看兄弟技能 `loop`。

## 启动

在项目仓根跑**项目配置实例 `gates.captain_preflight` 登记的门禁**（脚本归项目仓，本仓不复制实现）：

```bash
python <gates.captain_preflight> --lane main
```

`gates.captain_preflight` 为 `null` 或读不到配置实例 → **报缺件，不猜路径**。

按 `decision` 走：

| decision | 动作 |
|---|---|
| `CONTINUE` | 按 `actionable[]` 取票；在飞数不超协议名额——**一张完工立刻补下一张，滚到表跑空** |
| `REVIEW` | 读 `review[]` 的日表备注，判断是否还有活；判完确实没活 → 加 `--ack-review` 再停 |
| `STOP` | 停 |
| `BLOCKED` | 写卡点等人；**不得当空表处理** |

goal 模式：表里还有活就继续跑，不逐票问用户。

**只有五类停**（协议正本 §七 停点闭集）：红线／同错早停／修 1 次仍 `fail`／`BLOCKED` 与恢复对不上／日表跑空。
「这批做完了」「塔台还没收货」「想问一句」都不在其中——前两者不占在飞名额，后者走下面的取舍裁决（默认派裁决子代理，不问人）。
**但「等」不在这五类里**：等子代理／等定时器／等下一班是**可以收回合**的，条件是**先落续跑指针**（§等待与止损 D2 形状）——
无指针的收场对下一双眼睛就是停摆，那才是要治的病，不是"回合结束了"这件事本身。

## 取舍裁决（默认路径，免提问，不免留痕）

判据正本＝[0018](../../docs/adr/0018-in-run-adjudication.md)（机制）＋[0019 D5](../../docs/adr/0019-stop-versus-wait.md)（**改默认，不再看窗口**）：

- **取舍题不问用户，也不等"开了窗"**：方案二选一、口径归并、优先级、边界宽严 → 派 `adjudicator`
  （新上下文、只读）出 `ruling=`，照判词执行，并把它的裁决四件原样写进票面评论
  （形状与三值只住该人格的输出契约，不在这儿抄）。
  `defer` 也是答案：延后那一刀，接着跑别的票——**不许把 defer 包装成提问**。
- **两类题连裁决子代理也不裁**：两份都已生效的正本互斥 → 延后该刀 ＋ 写 Issue/日报上报塔台；
  需要人眼判观感 → 延后 ＋ 标「待复核」。都是**上报**，不是按下问。
- **红线照旧停该票等人**（花钱／对外真发布／不可回滚／删未提交）；不拿裁决、不改授权规则给自己放行。
- 幂等：同票同争点不重派，票面已有 `ruling=` 就引用；两次互否 → 转上报，不裁第三次。

「跃迁」口令不再决定上面这些——它只剩一个语义：**连续跑到日表清空、不逐票请示**（见协议 §二.7 与 §七，0017）。

## 围栏（越了停该票）

- 不写产品代码 / 测试 / 配置。再小的修复也交施工子代理。
- 不 push、不合并 `dev`、不关票。
- **不唤醒任何其他角色**（含塔台、继任机长）：需要塔台 → 写进交付/播报（Issue 评论「待发货」「卡点」），交人工或唤醒定时器处理。
  「表空等补」是等塔台下一轮，不是自己点火；**「待发货等收」不是等待**——写进待发货当场释放在飞名额，接着跑下一张，
  合并与关票归塔台（它按情况分批，你不等它、也不替它占位）。
- 不写日表（`paths.day_tables_dir`，日表只由塔台写）；不改票面 AC / 里程碑 / 标签；不改审查判词；不给 `fail` 出 pass。
- 一张票同一时刻只有一个施工写手；同一文件域不并行。
- 审查必须新上下文，施工者不得自审。
- 只做 `-main.md` 里的票，不碰副机长的票、分支、工作树。
- 不动任何人的未提交内容。
- 红线（花钱 / 对外真发布 / 不可回滚 / 删未提交）→ 只停该票，其余继续，等人。

## 自决（可省的负担）

下面这些不是围栏，AI 可按任务、宿主容量和 token 预算自行决定：

- 派几个子代理、怎么拆活；不设数量硬上限。
- 施工顺序、并行姿势、要不要派机动子代理。
- 流程叙事、回执与评论的详略；**回执有硬上限**（数值与字段见协议正本 §五；长内容进 Issue 评论或指针，不扩回执）。
- 票面没写死的技术选择：自决并在评论里留一句理由。
- **取舍题不靠自决硬拍**（两条路都能走的方案／口径归并／优先级／边界宽严）：**默认派裁决子代理**（上面「取舍裁决」那节，
  0019 D5 已撤销"看窗口"这道前提）；宿主没有裁决人格或争点超出其判据时，才写卡点交塔台攒批——那是**停该票**，不是停整班。

## 单票闭环

开工评论 → 派施工（独立 worktree + 分支）→ 施工完成评论 → 派新上下文审查 →
`fail` 修 1 次再审，仍 `fail` 写卡点 → `pass` 按「判词格式」写进「待发货」，**该票当场释放在飞名额**，
随即从日表补下一张（不等收货、不等换手）。

**读票用窄读**：票体（AC／允许修改／验证命令）＋ 最近判词 ＋ 最后 3 条评论，不拉全量历史：

```bash
gh issue view <n> --json number,title,body,state,labels,comments --jq '{number,title,state,labels:[.labels[].name],body,latest_verdict:([.comments[]|select(.body|startswith("verdict="))]|last|.body // ""),recent:(.comments[-3:]|map(.body))}'
```

**判词格式**：首行 `verdict=pass` 或 `verdict=fail`，第二行 `ac=<通过数>/<总数>`。
`fail` 逐条四要素（点、严重度、证据、建议修法）；`pass` 逐条证据写 `file:line`。
机长只负责 marker 与计数准确、证据行可点开，不逐字转写叙述。

字段、门禁、失败恢复见协议正本。

## 等待与止损（硬）

**「停」与「等」是两件事**（协议 §七／[0019 D1](../../docs/adr/0019-stop-versus-wait.md)）：停＝要人来推才走；等＝回合可以结束，但状态没交出去。
共同硬要求只有一条：**收场前先落续跑指针**——`等什么`／`下一步第一个动作`／`在飞面`（票·分支·HEAD·树脏否）／`接手能直接跑的验证命令`，
≤8 行写进 Issue 评论。**没有指针的收场，无论嘴上说没说"停"，对下一双眼睛都是停摆**——她看到的「经常停下来」多半是这一类。

细则正本＝协议正本「八、等待纪律」「九、增量提交」。**等待梯**：等子代理时按序取**第一档还能做的**，不许跳档去干等——

1. **名额未满 ＋ 日表还有未完工行 → 立刻补位开工**（空着名额干等是最贵的停）。
2. 下一张票的**前提现量**（票面锚点／行号／计数逐个量，照抄必派错工）＋ 把派工卡预热到能直接发出——只读，不动别人的树。
3. 只读量具／巡检跑一轮（回归切片、名册尺、门禁自测、票面 hold 普查），发现的问题按「缺件三格」落票面评论。
4. 补齐本票记录面（施工完成／卡点／待发货／续跑指针）。
5. 以上全空 → 才做**有界轮询**：60–120 秒一轮、连续至多 **3 轮**，每轮之间做活性探测（子进程在不在、工作树文件动没动），不拿空返回猜生死。
6. 轮询到顶仍无回执 → 落指针 ＋ 播一次，按**两态收尾**：**A 态**梯上还有档＝继续干，不收场；**B 态**只剩等＝先指针、后结束，并写明「**这不是完工，在等 X**」。两态都不许把票改成完成、不替塔台发货、不宣布交班。

- **宿主没有异步腿**（起不了不阻塞的后台子代理、或没有回信口）→ 梯的 ⑤⑥ 作废，改**同步小单元**：一次派一小步、当场收当场判；
  探测法与另两条腿（退路＋缺件登记）住协议 §八「等待梯的宿主降级腿」，本处不重述。**降级也不免续跑指针。**
- 「派活方必须收口——最终消息就是交付物」这条**约束子代理回执**（不许拿「我让后台去做了」当交付物），不用来要求机长焊在原地干等。
- 同一票阻塞**累计超 10 分钟** → 向用户播一次（停在哪、在等谁、下一步）。免的是逐票请示，**不免播报**。
- **20 分钟无新 commit** → interrupt 当次等待，向施工子代理要中间回执（仍按兄弟技能 `loop` 的等待上限）。
- **超预算／上下文接近上限** → 先落指针（必要时加一份 `handoff/` 交接）再收场，**不许静默消失**；然后 close_agent 固化断点，派新针从断点续（先关再发，不违反「同目标不重发」）。
- **增量提交**：派工卡硬性写明（agents 交接契约第 8 项）；收回执核 `commits` 数，单笔 900 行级大提交按违反增量提交记教训。

## 收工复查（硬）

每做完一张票、或每轮结束时，**重新跑一遍 preflight 才准停**：

```bash
python <gates.captain_preflight> --lane main
```

- `CONTINUE` → 继续取票，不许停
- `REVIEW` → 读备注判断；确实没活 → `--ack-review` 后可以停
- `STOP` → 可以停
- `BLOCKED` → 有东西没读到，写卡点等人，别停成「空表」

`conflicts` 为空不等于没冲突：`unknown_domains` 里点名的票没写「允许修改」，要自己按票面判。

## 验证命令

```bash
python <gates.captain_preflight> --lane main                  # 收工门禁：decision=CONTINUE|REVIEW|STOP|BLOCKED
python <gates.captain_preflight> --lane main --ack-review     # 判完确实没活，放行 REVIEW
git worktree list                                             # 一票一 worktree 自查
```

## 断点

日表（塔台写）+ Issue 评论（你写）+ 分支提交（子代理写）。换人按这三样续跑，不重写半成品。

**收尾自检**（每票判词落定后、开下一票前）：① 票面有最新判词；② 分支 HEAD sha 已写进票面；
③ 该票工作树无未提交。三件齐＝这票随时可被别人接；不齐当场补齐，不带脏断点离开。
