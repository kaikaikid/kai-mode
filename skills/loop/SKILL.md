# Loop —— 机长 / 副机长共用单票闭环

> 协议正文：[`loops/loop-protocol.md`](../../loops/loop-protocol.md)（v5 正本）。
> 本技能是导航壳：只写「谁在用、一轮怎么走、交什么」；条文冲突以正本和
> 框架仓旧裁决（项目仓 `docs/artifacts/adrs/`）为准。
> **不是用户入口**——用户入口是 `/kai-mode` 和角色口令；旧机场机器已退役，见 框架仓旧裁决。

## 谁在用

| 使用者 | 日表 | 名额 |
|---|---|---|
| 机长 | `.ai/tasks/YYYY-MM-DD-main.md` | 同时最多 2 张 issue，共 6 个子代理 |
| 副机长 | `.ai/tasks/YYYY-MM-DD-deputy.md` | 同上，名额独立计 |

每人的 6 个子代理＝**2 张 ×（1 施工 + 1 审查）＋ 2 个机动**；两张表不混读，票不跨表。

## 激活与目标

- 人工 `/机长`、`/副机长`，或 `/kai-mode` / 塔台拉起。
- **goal 模式**：激活后按日表连续跑，**不逐票问用户**；日表清空或踩红线才停。
- 只做日表里的票；表空不自己找活、不给自己加活、不改表。

## 起手四步

1. 读**自己**的日表；确认当前在飞票数 ≤ 2。
2. 按表顺序取票补到 2 张；两票文件域冲突 → 先开一张，另一张留表或写卡点请塔台调表。
3. 票面缺 AC / 边界 / 验证命令 → 不开工，写卡点。
4. 在 Issue 写「开工」评论（票号、分支、施工子代理、计划验证命令），然后派施工。

## 单票闭环（七步）

| # | 步 | 谁做 | 产出 |
|---|---|---|---|
| 1 | 领取 | 塔台写日表 | 票进入日表即完成领取，机长不再另写领取记录 |
| 2 | 开工评论 | 机长 | Issue 评论：分支、子代理、验证计划、预计断点 |
| 3 | 施工 | 施工子代理 | **独立 git worktree ＋ 分支**；先红后绿；commit（pathspec）＋ ≤40 行回执 |
| 4 | 施工完成评论 | 机长 | 回执要点：commit、改动文件、逐条 AC 证据、测试读数 |
| 5 | 审查 | 审查子代理（**新上下文**） | `verdict=pass\|fail` ＋ 每条 AC 的命令、输出、文件路径 |
| 6 | 判词处理 | 机长 | `fail` → 同一施工子代理修 **1 次**再审；再 `fail` → 卡点停该票 |
| 7 | 待发货 | 机长 | 把审查判词**原样**写进 Issue 评论「待发货」；不改判词 |

塔台下一轮只认审查判词发货；机长的总结不能替代判词。**机长不合并、不 push、不关票。**

## 状态与记录（单写手）

- **任务表只由塔台写**；机长只读，不改表、不给自己排票。
- **状态只由机长写 Issue 评论**：开工 / 施工完成 / 审查完成 / 待发货 / 卡点。
- 每条评论带证据：命令、输出摘要、commit、文件路径；长输出落文件，不贴全文。
- 断点三件套：**日表（塔台写的排班）＋ Issue 评论（机长写的状态与证据）＋ 分支提交（子代理写的代码）**。

## 失败、红线与断点

- 同一票失败 **1 次重试**；再失败 → 写「卡点」，停这张票，继续其他票。
- **红线**（花钱 / 对外真发布 / 不可回滚 / 删未提交内容）→ 只停**该票**并等人，其余票继续。
- 子代理越界（改禁止文件 / push / 动别人工作树）→ 停该票、保留证据、报塔台。
- 票面自相矛盾 → 卡点退回塔台 / 地勤，不自行改 AC。
- 继任机长读「日表 ＋ 该票 Issue 评论 ＋ 分支提交」从断点续跑；**不重写半成品**。

## 禁止事项

- 不写产品代码、测试、配置（再小的修复也交施工子代理）。
- 不 push、不合并 `dev`、不关票。
- 不改 `.ai/tasks/**`、不改票面 AC / 里程碑 / 标签、不改审查判词。
- 不动别人的分支、工作树、未提交内容。
- 不把状态写进日表、本地台账或聊天记忆。

## 子代理契约（摘要）

**派工卡**：票号、AC、允许/禁止修改、验证命令、环境口径（后端用主树正本解释器绝对路径；前端定向前在树内
`pnpm install --offline`，不 junction 主树依赖）、回执要求。**传指针不传全文。**

**回执**（≤40 行，JSON 或同构文本）：`ticket` / `role` / `verdict` / `files` / `commits` / `checks`
（测试读数、白名单核对）/ `summary` / `evidence`（file:line）/ `risks` / `next`；禁止贴 diff 全文、测试原始输出、issue 正文。

**审查**：必须新上下文，施工者不得给自己出 pass；只读，不改代码。**机动子代理**只做环境自检、跑门、复现 flaky、
整理 AC 对照表；要改码交该票施工子代理。
