# kai-boom-idea-log —— 想法入库

> 一份想法＝**本地详情文件（正本）** ＋ **汇总票一条简述（分发面）**。
> 两个落点都从项目配置实例读，不写死目录名与票号。

## 进场

| 用户说法 | 动作 |
|---|---|
| 「记个想法」「丢进想法池」「记到 #N」 | 直接走流程 |
| 随口抛出项目想法／灵感／吐槽（不是提问、不是闲聊） | 先一句「要记进想法池吗？」，点头才做；被拒则同一条不再问 |
| 纯闲聊、技术问答里顺带的零星念头 | 不记，等用户主动说 |

## 流程

1. **查重**：`ls` 想法目录看有无同类旧想法。相似 → 追加「处理记录」，不新开文件、不再贴新评论
   （最多在原评论下补一句「有新进展，见文件」）。
2. **编号 N**：已有文件数 + 1，与汇总票评论区「想法 #N」序列对齐。
3. **写本地文件**：`<ideas_dir>/YYYY-MM-DD-<kebab-slug>.md`，用下方模板。「用户原话」一字不改；
   「AI 整理」里的猜测必须标注为猜测，不编造用户意图。
4. **贴简述**：把评论正文写成 UTF-8 临时文件，再 `gh issue comment <汇总票号> --body-file <临时文件>`，
   贴完删临时文件（避开 Windows 引号／编码坑）。
5. **只暂存这一个文件**：`git add <该文件>`。**禁 `git add -A`**；commit／push 等用户授权。
6. **回报**：本地文件路径 + 评论 URL。

## 文件模板

```markdown
# 想法 #N — <标题>

- 日期：YYYY-MM-DD · 状态：已入库 · 来源：<汇总票#>（评论 <URL>）
- 标签：<功能/体验/性能/工程/其他>

## 用户原话

> <一字不改>

## AI 整理

<背景、可能的落点、与现有模块的关系、初步取舍——引申部分注明「猜测」>

## 待办

- [ ] 整理/去重 → 决定是否开票（开票时回链本文件）

## 处理记录

- YYYY-MM-DD 入库：建本文件，汇总票已贴简述
```

## 评论模板（远端只留简述）

```markdown
### 想法 #N 已入库

**标题：** <一句话>
**原话：** <短句直引；太长则浓缩并注明「全文见文件」>
**详情：** `<ideas_dir>/YYYY-MM-DD-<slug>.md`（已入库本仓库，随 git 同步）

> 状态：已入库，待整理/分类/开票。详情正文存本地文件，本池只留简述。
```

## 毕业与回写

想法被整理成票后（通常发生在整理会话，不是本技能干的）：
文件「状态」改 `已分发`，「处理记录」追加票号并勾掉待办；在汇总票原评论处回链一条「已分发 → 票 #M」。

## 完成判据

- [ ] 本地文件已写，编号与汇总票序列一致
- [ ] 汇总票只有简述，没有长文与代码块
- [ ] 只暂存了这一个文件（`git status --short` 自查）
- [ ] 回报里给了文件路径与评论 URL

## 禁止

- 开票、改 milestone、动代码（分发不是本技能的事）。
- 在汇总票里贴全文、贴代码、贴长对话。
- 手工重编号（日期前缀天然排序，编号只增不减）。
- 把想法写进 `docs/` 治理区（受 docs 门禁扫，且那层放裁决不放念头）。

## 失败降级

| 情况 | 处理 |
|---|---|
| `gh` 未登录／断网 | 文件照写照 add，「处理记录」标「远端未贴，待补」，并明确告诉用户评论没贴出去 |
| 项目配置缺 `paths.ideas_dir` 或汇总票号 | 报缺件，不猜目录、不猜票号 |
| 想法与既有想法高度重合 | 合并进旧文件，不新建 |

## 验证命令

```bash
git status --short                 # 确认只 add 了想法文件
gh issue view <汇总票号> --json comments --jq '.comments[-1].url'
```
